/Comandos de Claude Code

Todos los comandos de barra de Claude Code explicados con palabras sencillas: qué hacen y cuándo son más útiles.

claude
❯

    Busca un comando según lo que quieres hacer

    Elige una situación; los comandos aparecen en el orden en que conviene probarlos.

    • Claude rompió algo y quiero deshacerlo: /rewind /diff
    • Empezar desde cero una tarea sin relación: /clear /resume
    • La conversación es larga y Claude va lento u olvida cosas: /context /compact /autocompact
    • Continuar el trabajo que dejé sin terminar ayer: /resume /rename /recap
    • Ver un plan antes de un cambio grande: /plan /effort /model
    • Hacer que Claude responda siempre en mi idioma: /init /memory
    • Gastar menos dinero y consumir menos uso: /usage /model /effort /context
    • Revisar el trabajo antes de hacer commit o de publicarlo: /diff /code-review /security-review /verify
    • Hacer varias cosas a la vez o trabajar en segundo plano: /fork /subtask /background /tasks /batch
    • Repetir una tarea o ejecutarla según un horario: /loop /schedule /goal
    • Demasiadas solicitudes de permiso: /permissions /fewer-permission-prompts
    • Conectar herramientas o añadir nuevas capacidades: /mcp /plugin /skills
    • Crear diapositivas, diseños o gráficos: /slides /design /dataviz /artifacts
    • Dejar el equipo y seguir en el teléfono: /remote-control /mobile /desktop
    • El propio Claude Code funciona mal: /doctor /status /debug /bug
    • Aprender Claude Code a fondo: /powerup /help /insights

    Etiquetas de seguridad

    Ten especial cuidado con los comandos marcados así.

      Conversación y contexto

      Empezar, compactar, rebobinar y retomar conversaciones; gestionar la ventana de contexto

      /clear [name]

      Empieza una conversación nueva con el contexto vacío, pero conserva la memoria del proyecto. La conversación anterior se guarda y puedes volver a abrirla con /resume; si escribes un nombre, sirve de etiqueta en el selector.

      Mejor uso: Cuando terminas una función y pasas a una tarea sin relación: /clear funcion-de-inicio-de-sesion. El contexto viejo deja de interferir y el uso baja.

      /compact [instructions]

      Resume la conversación hasta ahora para liberar espacio de contexto y sigue en la misma conversación. Puedes añadir instrucciones para indicar qué debe conservar el resumen.

      Mejor uso: Después de una sesión larga: /compact conserva el esquema de la base de datos y la lista de errores pendientes.

      /context [all]

      Muestra el uso del contexto como una cuadrícula de colores, con sugerencias para optimizar y avisos de capacidad. all muestra el desglose por elemento.

      Mejor uso: Cuando Claude parece olvidar cosas o el uso sube rápido, ejecuta /context para ver si archivos grandes o la salida de herramientas están llenando la ventana.

      /plan [description]

      Entra en el modo plan: Claude investiga y propone un plan antes de editar. Si añades una descripción, empieza esa tarea de inmediato.

      Mejor uso: Antes de un cambio grande: /plan corrige el error de autenticación, revisa y luego aprueba.

      /resume [session]

      Retoma una conversación por su ID o nombre, o abre el selector de sesiones. Las sesiones en segundo plano aparecen marcadas con bg.

      Mejor uso: Ayer cerraste el portátil a mitad de una tarea: /resume y elige la conversación de ayer.

      /rewind

      Devuelve la conversación, el código o ambos a un punto de control anterior, o resume a partir de un mensaje que elijas.

      Mejor uso: Claude rompió varios archivos: ejecuta /rewind, elige el mensaje anterior a los cambios y restaura el código y la conversación.

      /autocompact [auto|<tokens>]

      Define cuánto se llena la ventana de contexto antes de la compactación automática, por ejemplo 500k; auto vuelve al valor predeterminado ajustado al modelo. Se guarda en la configuración de usuario y se aplica al momento.

      Mejor uso: Una tarea larga se interrumpe por compactaciones frecuentes: /autocompact 500k.

      /branch [name]

      Crea una rama de la conversación en este punto y cambia a ella; la original se conserva y puedes volver con /resume. (Es una rama de la conversación, no una rama de Git).

      Mejor uso: Dudas entre dos enfoques: /branch probar-plan-b; si no funciona, vuelve atrás y sigue con el plan A.

      /btw [question]

      Hace una pregunta aparte sobre la sesión actual sin añadirla a la conversación. Sin pregunta, muestra tu última pregunta aparte.

      Mejor uso: En medio de una tarea quieres entender un error: /btw qué significa este 404, sin desviar el hilo principal.

      /copy [N]

      Copia la última respuesta al portapapeles; /copy 2 copia la penúltima. Si hay bloques de código, un selector te deja copiar uno solo; pulsa w para escribirlo en un archivo (útil por SSH).

      Mejor uso: Claude escribió un fragmento de código o un comando: /copy y pégalo donde lo necesites.

      /export [filename]

      Exporta la conversación como texto plano: directamente a un archivo si le das un nombre o, si no, mediante un diálogo para copiar o guardar.

      Mejor uso: Para archivar una sesión de depuración valiosa: /export notas-de-depuracion.txt.

      /goal [condition|clear]

      Fija un objetivo: Claude sigue trabajando turno tras turno hasta que se cumple la condición o se borra el objetivo. Sin argumento, muestra el objetivo actual; clear (o stop, off, …) lo elimina.

      Mejor uso: /goal todas las pruebas pasan, y deja que itere hasta que todo esté en verde.

      /memory

      Edita los archivos de memoria CLAUDE.md, activa o desactiva la memoria automática y muestra sus entradas.

      Mejor uso: Quieres que todas las respuestas estén en tu idioma: abre /memory y añade una línea como «Responde siempre en español».

      /recap

      Genera cuando lo pides un resumen de una línea de la sesión actual.

      Mejor uso: Vuelves de una reunión y perdiste el hilo: /recap.

      /rename [name]

      Cambia el nombre de la sesión y lo muestra en la barra del prompt; sin nombre, genera uno a partir de la conversación.

      Mejor uso: Con muchas sesiones abiertas: /rename backtest para que destaque en /resume.

      Modelo y razonamiento

      Cambiar de modelo, el esfuerzo de razonamiento y la velocidad

      /model [model]

      Cambia de modelo y lo guarda como predeterminado para las sesiones nuevas. Sin argumento abre un selector; las flechas izquierda/derecha ajustan el esfuerzo en los modelos compatibles; pulsa s en una fila para cambiar solo en esta sesión.

      Mejor uso: Usa un modelo más rápido para cambios pequeños; cambia con /model opus cuando un error se complica.

      /advisor [model|off]

      Activa o desactiva la herramienta de asesor, que consulta a un segundo modelo en los momentos clave. Acepta fable, opus, sonnet o un ID de modelo completo (fable requiere acceso). Sin argumento abre un selector.

      Mejor uso: Trabaja con un modelo más rápido, pero recibe una segunda opinión más potente en las decisiones clave: /advisor opus.

      /effort [level|auto|status|ultracode [on|off]]

      Define el nivel de esfuerzo: de low a xhigh, max o auto; status lo muestra. max vale solo para la sesión. ultracode on|off activa o desactiva ultracode.

      Mejor uso: Para cazar un error intermitente: /effort high; para corregir una errata: /effort low.

      /fast [on|off]

      Activa o desactiva el modo rápido (mismo modelo, salida más rápida). Puedes cambiarlo en medio de una respuesta; el turno en curso termina a su velocidad original. Consulta la documentación oficial del modo rápido para ver los precios.

      Mejor uso: Si tienes prisa: /fast on; si no, /fast off.

      /output-style [style]

      Muestra los estilos de salida o cambia a uno, por ejemplo /output-style concise.

      Mejor uso: Ejecuta /output-style sin argumento para ver qué hay disponible y luego elige uno (por ejemplo, un estilo más conciso).

      Proyecto y archivos

      Configurar la memoria del proyecto, añadir carpetas, revisar cambios

      /init

      Inicializa el proyecto con una guía CLAUDE.md que lee cada sesión nueva. Ofrece /import si encuentra configuración de Codex o Gemini CLI.

      Mejor uso: Lo primero en un repositorio nuevo: /init, y luego mejóralo con /memory.

      /add-dir <path>

      Añade una carpeta de trabajo para acceder a sus archivos en esta sesión, sin moverte. Las rutas parciales se autocompletan con Tab. La mayor parte de la configuración .claude/ de la carpeta añadida no se detecta, y la mayoría de las rutas de red no se pueden añadir.

      Mejor uso: El frontend y el backend están uno al lado del otro: /add-dir ../backend.

      /cd <path>

      Mueve la sesión a otra carpeta de trabajo y conserva la conversación. A diferencia de /add-dir, /cd cambia el lugar donde vive la sesión.

      Mejor uso: Empezaste en la carpeta equivocada: /cd ~/projects/website en lugar de empezar de nuevo.

      /diff

      Revisa los cambios de tu árbol de trabajo, incluidos los que Claude ha hecho hasta ahora.

      Mejor uso: Antes de hacer commit, /diff para ver exactamente qué cambió.

      /import [codex|gemini|cursor] [--dry-run] [--yes]

      Importa archivos de instrucciones, servidores MCP, comandos, subagentes y habilidades de OpenAI Codex, Gemini CLI o Cursor. --dry-run muestra una vista previa. No está disponible en algunos proveedores en la nube; importar desde Cursor requiere v2.1.265 o posterior.

      Mejor uso: Si vienes de Cursor: primero /import cursor --dry-run y después importa de verdad.

      /insights

      Genera un informe HTML de tus sesiones recientes en este equipo: proyectos, hábitos, dónde fallan las cosas y funciones que vale la pena probar. No está disponible en sesiones en la nube.

      Mejor uso: Después de unas semanas, ejecuta /insights para descubrir funciones que nunca probaste.

      /team-onboarding

      Analiza tus sesiones, comandos y uso de MCP de los últimos 30 días y escribe una guía en Markdown que un compañero puede pegar como su primer mensaje.

      Mejor uso: Llega alguien nuevo al equipo: ejecuta /team-onboarding y envíale la guía.

      Revisión y verificación

      Encontrar errores y vulnerabilidades, limpiar el código, ejecutar la aplicación para verificar

      /code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

      Revisa el diff actual, o un PR, una rama o una ruta, en busca de errores de funcionamiento. --fix aplica las correcciones, --comment publica en el PR de GitHub o el MR de GitLab, ultra hace una revisión profunda en la nube.

      Mejor uso: Antes de hacer commit: /code-review high --fix. Para un PR: /code-review high 1234.

      /run

      Inicia y maneja la aplicación de tu proyecto para ver un cambio funcionando.

      Mejor uso: /run para arrancar el sitio y hacer una captura de la nueva página de inicio.

      /run-skill-generator

      Escribe una habilidad propia del proyecto que enseña a /run y /verify a compilar, iniciar y manejar tu aplicación desde un entorno limpio.

      Mejor uso: El arranque necesita varios pasos (primero la base de datos, etc.): ejecútalo una vez y después /run funciona sin más.

      /security-review

      Analiza el diff de tu rama frente a la rama predeterminada de origin en busca de vulnerabilidades como inyección, problemas de autenticación o exposición de datos. Necesita un remoto origin.

      Mejor uso: Antes de publicar algo que toque autenticación, pagos o datos de usuarios.

      /simplify [target]

      Cuatro agentes en paralelo revisan el código cambiado buscando reutilización, simplificación, eficiencia y nivel de abstracción, y luego aplican las correcciones. No busca errores de funcionamiento; para eso usa /code-review.

      Mejor uso: La función ya funciona y quieres un código más limpio: /simplify.

      /ultrareview [PR or branch]

      Revisión profunda con varios agentes en un sandbox en la nube. La forma preferida es /code-review ultra; /ultrareview es un alias. Incluye 3 ejecuciones gratis en Pro, Max y Ultra; después requiere créditos de uso.

      Mejor uso: Antes de una versión importante: /code-review ultra.

      /verify

      Compila, ejecuta y observa tu aplicación para confirmar que un cambio funciona, en lugar de fiarse de las pruebas o de la comprobación de tipos. Solo se ejecuta cuando lo invocas.

      Mejor uso: Cambiaste el comportamiento de un botón: /verify para que de verdad haga clic en él.

      Trabajo en paralelo y en segundo plano

      Ejecutar varios agentes a la vez o pasar trabajo a segundo plano

      /agents

      Muestra un recordatorio de que puedes pedirle a Claude que cree o gestione subagentes, o editar .claude/agents/ directamente. En v2.1.197 y anteriores abría un gestor interactivo.

      Mejor uso: Simplemente pídelo: «Crea un subagente que solo escriba pruebas».

      /background [prompt]

      Separa la sesión para que siga como agente en segundo plano y libera la terminal. Opcionalmente, antes envía una instrucción más. Síguela con claude agents.

      Mejor uso: Un trabajo de 30 minutos: /bg escribe los resultados en report.md cuando termines.

      /batch <instruction>

      Coordina cambios grandes en paralelo: investiga el código, divide el trabajo en 5–30 unidades independientes y presenta un plan; tras tu aprobación, un subagente en segundo plano por unidad la implementa y la prueba en su propio worktree. Requiere un repositorio git o un hook WorktreeCreate.

      Mejor uso: /batch migra src/ de JavaScript a TypeScript.

      /fork [prompt]

      Copia la conversación en una sesión nueva en segundo plano mientras tú sigues trabajando aquí. Con un prompt, la copia empieza de inmediato; normalmente se le indica que primero cree su propio worktree.

      Mejor uso: Trabajas en la función A y quieres una corrección aparte en paralelo: /fork corrige la alineación del pie de página.

      /list-agents

      Lista los subagentes, compañeros y otras sesiones a los que Claude puede enviar mensajes, con el nombre que debes usar para cada uno. Solo donde los mensajes entre sesiones están activados.

      Mejor uso: Si coordinas varias sesiones: comprueba cómo se llama cada una.

      /stop

      Detiene la sesión en segundo plano a la que estás conectado; la transcripción y el worktree se conservan. Para desconectarte sin detenerla, usa /exit o pulsa ←.

      Mejor uso: Un trabajo en segundo plano se desvió: /stop.

      /subtask <task>

      Lanza un subagente bifurcado que hereda la conversación y devuelve su resultado aquí. La diferencia con /fork: /subtask devuelve el resultado aquí, mientras que /fork crea una sesión aparte.

      Mejor uso: /subtask documenta estos endpoints de la API mientras sigues programando.

      /tasks

      Muestra y gestiona el trabajo en segundo plano de esta sesión, incluidos los subagentes que ya terminaron.

      Mejor uso: Mira el avance de pruebas o subagentes en segundo plano con /tasks.

      /workflow-authoring

      Carga la referencia para escribir scripts de flujos de trabajo dinámicos. Claude normalmente la carga solo; ejecútalo antes de editar a mano un script guardado. Solo donde los flujos de trabajo dinámicos están activados.

      Mejor uso: Antes de editar a mano un script de flujo de trabajo guardado.

      /workflows

      Abre la vista de progreso de flujos de trabajo para ver, pausar, reanudar o guardar flujos en curso y terminados.

      Mejor uso: Vigila un flujo de trabajo que tarda mucho.

      Automatización y programación

      Repetir cada cierto tiempo, ejecutar según un horario, corregir pull requests automáticamente

      /loop [interval] [prompt]

      Ejecuta un prompt una y otra vez mientras la sesión sigue abierta. Si omites el intervalo, Claude marca su propio ritmo; si omites el prompt, ejecuta el prompt de mantenimiento integrado o tu loop.md.

      Mejor uso: /loop 5m comprueba si terminó el despliegue. Para ejecuciones que sigan con el equipo apagado, usa /schedule.

      /autofix-pr [prompt]

      Lanza una sesión en la nube que vigila el PR de la rama actual y sube correcciones cuando falla la CI o hay comentarios de revisión. Requiere la CLI gh y sesiones en la nube.

      Mejor uso: /autofix-pr corrige solo errores de lint y de tipos.

      /deep-research <question>

      Un flujo de trabajo incluido que lanza muchas búsquedas web, obtiene y contrasta fuentes y escribe un informe con citas. Se ejecuta en segundo plano.

      Mejor uso: /deep-research compara precios y calidad de las principales herramientas de video con IA.

      /schedule [description]

      Crea, actualiza, lista o ejecuta tareas programadas en la nube (antes llamadas rutinas) mediante una conversación guiada. No está disponible con una clave de API de Console.

      Mejor uso: /schedule cada día laborable a las 9, resume los issues nuevos del repositorio.

      Artefactos, diapositivas y diseño

      Crear páginas, presentaciones, diseños y gráficos para compartir

      /artifact-capabilities

      Carga la referencia de las capacidades de ejecución de los artefactos, como llamar a conectores u ofrecer descargas, y cuáles tiene tu cuenta. Claude normalmente la carga solo.

      Mejor uso: Antes de crear una página que mucha gente va a rellenar.

      /artifact-diagramming

      Carga una guía de diagramas para artefactos: cuándo ayuda un diagrama, qué dibujar y SVG que se lee bien en temas claros y oscuros.

      Mejor uso: Cuando necesitas un diagrama de arquitectura claro.

      /artifacts

      Lista los artefactos que te pertenecen o que otros comparten contigo, y luego conecta uno, lo abre o copia su enlace. Donde los artefactos están disponibles.

      Mejor uso: Encuentra el panel de la semana pasada y sigue editándolo.

      /dataviz [request]

      Guía para diseñar gráficos: elige el tipo de gráfico, asigna los colores según su función y valida la paleta (seguridad para daltonismo y contraste) con un script incluido.

      Mejor uso: /dataviz convierte esta tabla de ventas mensuales en un gráfico de tendencia.

      /design [brief]

      Crea bocetos de interfaz, flujos, páginas de aterrizaje o pósteres como mesas de trabajo en un solo lienzo (un artefacto de Claude Design); edítalos en un navegador de escritorio y expórtalos en PNG o PDF. No está disponible en Bedrock, Vertex ni otras plataformas de terceros.

      Mejor uso: /design una pantalla de configuración para una app de banca móvil.

      /design consent

      Concede o retira el acceso de Claude a Claude Design. Cuando Claude te pida ejecutar /design consent, escríbelo tú mismo.

      Mejor uso: Cuando se te pida, escribe tú mismo /design consent.

      /design-login

      Autoriza el acceso al sistema de diseño para /design-sync con tu cuenta de claude.ai, cuando /design-sync o /design consent te lo pidan.

      Mejor uso: Ejecútalo cuando /design-sync te pida iniciar sesión.

      /design-sync [hint]

      Convierte y sube el sistema de diseño React de tu repositorio a Claude Design para que los diseños usen tus componentes reales. La primera sincronización puede tardar horas en repositorios grandes. Usa el sitio independiente claude.ai/design, que cierra a más tardar el 14 de diciembre de 2026.

      Mejor uso: /design-sync Acme DS (ten en cuenta la fecha de cierre indicada arriba).

      /slides [brief]

      Crea un artefacto de Claude Slides a partir de tus indicaciones. Requiere una sesión con artefactos y una cuenta donde esté disponible la plantilla de Slides.

      Mejor uso: /slides una revisión trimestral para la dirección, 8 diapositivas.

      Complementos, habilidades e integraciones

      Ampliar Claude con complementos, habilidades, servidores MCP e integraciones con el navegador y el IDE

      /mcp [reconnect (<server>|all)|enable|disable [<server>|all]]

      Gestiona las conexiones a servidores MCP y OAuth. Sin argumento abre la lista; reconnect, enable o disable con el nombre de un servidor o all actúan directamente.

      Mejor uso: Un conector falló o necesita autenticación: /mcp reconnect all.

      /chrome

      Configura los ajustes de Claude in Chrome.

      Mejor uso: Al conectar la extensión de Chrome por primera vez.

      /claude-api [subcommand]

      Carga la referencia de la API de Claude y de Managed Agents para el lenguaje de tu proyecto; se activa sola cuando el código importa anthropic. Los subcomandos incluyen migrate, upgrade, api-version, cost-optimize, latency-optimize, build-eval, prompt-audit.

      Mejor uso: Reduce el gasto de API de tu aplicación: /claude-api cost-optimize.

      /claude-in-chrome [task]

      Hace que Claude realice una tarea en tu navegador mediante Claude in Chrome, como probar una página o leer los registros de la consola. Requiere la integración con Chrome (por ejemplo, claude --chrome).

      Mejor uso: /claude-in-chrome prueba el registro de usuarios en mi sitio local e informa de los errores.

      /ide

      Gestiona las integraciones con IDE y muestra su estado.

      Mejor uso: Comprueba la conexión cuando los cambios no aparecen en tu editor.

      /install-github-app

      Instala la Claude GitHub App en un repositorio y, si quieres, configura flujos de trabajo y secretos de GitHub Actions. Solo github.com.

      Mejor uso: Para mencionar a Claude en issues y PR y que trabaje ahí.

      /install-slack-app

      Instala la app de Claude para Slack mediante un flujo OAuth en el navegador.

      Mejor uso: Tu equipo quiere a Claude en Slack.

      /plugin [subcommand]

      Gestiona complementos. Sin argumento abre el menú; list, install, enable, disable actúan directamente. Ejecuta /reload-plugins si el resumen de instalación lo indica.

      Mejor uso: Explora con /plugin e instala uno que encaje con tu trabajo.

      /plugin-authoring

      Carga la referencia para escribir un mod. Es una habilidad de un complemento integrado, que puedes desactivar en /plugin.

      Mejor uso: Cuando quieres un pequeño panel lateral que se quede junto al chat.

      /reload-plugins [--force]

      Recarga los complementos activos sin reiniciar e informa de los errores de carga. Si la recarga cambiaría las herramientas MCP cargadas e invalidaría la caché del prompt, avisa y no la hace salvo que pases --force.

      Mejor uso: Justo después de instalar un complemento que lo pide.

      /reload-skills

      Vuelve a explorar las carpetas de habilidades y comandos para que las habilidades añadidas o cambiadas durante la sesión estén disponibles sin reiniciar.

      Mejor uso: Acabas de escribir una habilidad propia y la quieres usar ya.

      /skill-doctor

      Muestra el costo de contexto y el uso de cada habilidad para que encuentres cuáles desactivar.

      Mejor uso: Ejecútalo de vez en cuando para quitar habilidades que no usas.

      /skills

      Lista las habilidades con filtros. t ordena por número de tokens, Space/Enter cambia la visibilidad de una habilidad para Claude y para el menú /, Esc guarda y cierra.

      Mejor uso: Demasiadas habilidades: /skills, pulsa t y oculta las pesadas que no usas.

      Permisos y seguridad

      Controlar qué puede hacer Claude y qué necesita tu aprobación

      /permissions

      Gestiona las reglas de permitir, preguntar y denegar para las herramientas: verlas por ámbito, añadir o quitar reglas, gestionar carpetas de trabajo y revisar la pestaña Recently blocked (llamadas que frenó el modo automático) y las reglas del clasificador.

      Mejor uso: Te cansaste de aprobar npm test cada vez: permítelo aquí.

      /auto-mode-setup

      Redacta entradas de autoMode.environment a partir de tu proyecto y tus sesiones recientes para que las revises y guardes. Tiene requisitos de versión y de plan.

      Mejor uso: Cuando el modo automático bloquea una y otra vez acciones rutinarias.

      /fewer-permission-prompts

      Revisa las transcripciones en busca de llamadas comunes de solo lectura a Bash y MCP, y añade una lista de permitidos priorizada al .claude/settings.json del proyecto.

      Mejor uso: Ejecútalo una vez cuando las solicitudes de aprobación no dejan de interrumpirte.

      /hooks

      Muestra la configuración de los hooks.

      Mejor uso: Revisa qué hay configurado cuando un hook parece romper cada cambio.

      /privacy-settings

      Muestra y actualiza la configuración de privacidad. Solo Pro, Max y Ultra.

      Mejor uso: Para comprobar cómo se usan tus datos.

      /sandbox

      Activa o desactiva el modo sandbox, solo en plataformas compatibles.

      Mejor uso: Actívalo antes de ejecutar scripts que no conoces.

      /update-config [request]

      Describe un cambio de configuración (permitir un comando, definir una variable de entorno, añadir un hook) y Claude edita el settings.json correspondiente. Usa /config para el tema y el modelo.

      Mejor uso: /update-config ejecuta prettier después de cada edición de archivo.

      Configuración e interfaz

      Tema, colores, línea de estado, atajos de teclado, voz

      /color [color|default]

      Define el color de la barra del prompt para esta sesión: red, blue, green, yellow, purple, orange, pink o cyan; default lo restablece y sin argumento elige un color al azar.

      Mejor uso: Marca una sesión de producción con /color red.

      /config [key=value ...]

      Abre la configuración para el tema, el modelo, el estilo de salida y más, o define pares key=value directamente, por ejemplo /config theme=dark. /config --help lista las claves.

      Mejor uso: /config theme=dark.

      /focus

      Activa o desactiva una vista que muestra solo tu último prompt, un resumen de una línea de las herramientas y la respuesta final. Solo con el renderizado a pantalla completa.

      Mejor uso: Oculta los pasos intermedios y ve solo el resultado.

      /keybindings

      Abre tu archivo de atajos de teclado.

      Mejor uso: Asigna las acciones a las teclas que ya conoces.

      /scroll-speed

      Ajusta la velocidad de desplazamiento de la rueda del mouse. Solo con el renderizado a pantalla completa; no en la terminal de JetBrains.

      Mejor uso: Redúcela cuando un solo paso de la rueda salta demasiado.

      /statusline

      Configura la línea de estado; describe lo que quieres o ejecútalo sin argumentos para basarla en el prompt de tu shell.

      Mejor uso: /statusline muestra el modelo y la rama de git.

      /terminal-setup

      Instala Shift+Enter para saltos de línea en VS Code, Cursor, Devin Desktop, Alacritty o Zed; en Apple Terminal activa Option+Enter y desactiva la campana; en iTerm2 activa el acceso al portapapeles para /copy.

      Mejor uso: Enter envía prompts a medio escribir: ejecútalo una vez.

      /theme

      Cambia el tema de colores: auto, claro y oscuro, aptos para daltonismo, ANSI y temas personalizados.

      Mejor uso: Cambia a un tema oscuro por la noche.

      /tui [default|fullscreen]

      Define el renderizador de la terminal y reinicia con la conversación intacta. fullscreen es el renderizador sin parpadeo. Sin argumento, muestra el renderizador actual.

      Mejor uso: La pantalla parpadea: /tui fullscreen.

      /voice [hold|tap|off]

      Activa o desactiva el dictado por voz o elige un modo (hold, tap). Requiere una cuenta de Claude.ai.

      Mejor uso: Dicta instrucciones en lugar de escribirlas.

      Cuenta y uso

      Iniciar sesión, revisar límites y costos, mejorar el plan

      /usage

      Muestra el costo de la sesión, el gasto de hoy, de esta semana y de este mes, los límites de uso del plan y estadísticas de actividad, incluido lo que cuenta para los límites del plan en las suscripciones. /stats abre la pestaña Stats. Cada aviso indica su causa y un arreglo de una línea; pulsa f para aplicar los arreglos.

      Mejor uso: Revisa /usage antes de decidir si cambias a un modelo más barato.

      /login

      Inicia sesión en tu cuenta de Anthropic.

      Mejor uso: En un equipo nuevo o cuando la sesión caducó.

      /logout

      Cierra la sesión de tu cuenta de Anthropic.

      Mejor uso: Después de usar un equipo compartido.

      /passes

      Comparte una semana gratis de Claude Code con amigos; solo aparece en cuentas que cumplen los requisitos.

      Mejor uso: Invita a un amigo a probarlo.

      /rate-limit-options

      Muestra formas de seguir trabajando cuando un límite de claude.ai te bloquea: esperar y continuar automáticamente, añadir créditos de uso o mejorar el plan. Requiere una suscripción a claude.ai.

      Mejor uso: El límite te bloqueó por la noche: elige continuar automáticamente cuando se restablezca.

      /status

      Abre la configuración en la pestaña Status: versión, modelo, cuenta y conectividad. Funciona mientras Claude responde.

      Mejor uso: Haz una captura de /status antes de pedir ayuda.

      /upgrade

      Abre la página para mejorar el plan en tu navegador.

      Mejor uso: Cuando llegas a los límites una y otra vez.

      /usage-credits

      Configura o solicita créditos de uso; los miembros de Team y Enterprise sin acceso a la facturación envían una solicitud a su administrador. Antes era /extra-usage.

      Mejor uso: Pide créditos a tu administrador cuando el equipo se queda sin ellos.

      Nube, acceso remoto y otros dispositivos

      Pasar el trabajo entre escritorio, móvil, web y nube

      /desktop

      Continúa la sesión en la aplicación Claude Code Desktop. Requiere macOS o Windows x64 y una suscripción a Claude.

      Mejor uso: Pasa de la terminal a la aplicación de escritorio.

      /mobile

      Muestra un código QR para descargar la aplicación móvil de Claude.

      Mejor uso: Para seguir el trabajo desde tu teléfono.

      /remote-control

      Hace que esta sesión esté disponible para Remote Control desde claude.ai. Requiere una suscripción a claude.ai.

      Mejor uso: Deja la tarea en marcha y dirígela desde tu teléfono: /rc.

      /remote-env

      Elige el entorno en la nube predeterminado para las sesiones en la nube iniciadas desde la CLI.

      Mejor uso: Elige uno predeterminado cuando tienes varios entornos.

      /setup-bedrock

      Configura con un asistente la autenticación, la región y los modelos fijos de Amazon Bedrock. Está oculto en el menú hasta que se define CLAUDE_CODE_USE_BEDROCK=1; escríbelo completo.

      Mejor uso: Tu empresa usa Claude a través de AWS.

      /setup-vertex

      Configura con un asistente Agent Platform de Google Cloud. Está oculto hasta que se define CLAUDE_CODE_USE_VERTEX=1; escríbelo completo.

      Mejor uso: Tu empresa usa Claude a través de Google Cloud.

      /teleport

      Trae una sesión en la nube a esta terminal, con su rama y su conversación. Requiere una suscripción a claude.ai.

      Mejor uso: Continúa en local una tarea que empezaste en la web.

      /web-setup

      Conecta GitHub para las sesiones en la nube usando tus credenciales locales de gh.

      Mejor uso: Antes de tu primera sesión en la nube.

      Diagnóstico y comentarios

      Empieza aquí cuando algo falla

      /doctor [prompt-audit [path]]

      Hace un chequeo de la instalación, la configuración, las extensiones y CLAUDE.md, y propone correcciones que Claude aplica después de que confirmes. prompt-audit revisa en cambio tus instrucciones.

      Mejor uso: Algo parece roto: empieza con /doctor.

      /help

      Muestra la ayuda y los comandos disponibles.

      Mejor uso: Olvidaste un comando: /help, o escribe / y unas letras.

      /powerup

      Lecciones interactivas con demostraciones animadas que enseñan las funciones de Claude Code.

      Mejor uso: El mejor punto de partida estructurado para quien empieza.

      /bug [report]

      Informa de un error o comparte tu conversación; tú eliges cuánto historial incluir y confirmas antes de que se envíe nada.

      Mejor uso: Cuando el propio Claude Code se comporta mal.

      /debug [description]

      Activa el registro de depuración desde este momento y busca el problema leyendo el registro de depuración de la sesión. Opcionalmente, describe el problema.

      Mejor uso: /debug el servidor MCP no logra conectarse.

      /exit

      Sale de la CLI. En una sesión en segundo plano conectada, se desconecta y la sesión sigue en marcha.

      Mejor uso: Terminaste por hoy.

      /feedback [report]

      Envía comentarios sobre el producto con el mismo diálogo y el mismo paso de consentimiento que /bug.

      Mejor uso: Pide una función nueva.

      /heapdump

      Escribe en el Escritorio una instantánea del heap y un desglose de la memoria para diagnosticar un uso alto de memoria. Comparte solo el -diagnostics.json; el .heapsnapshot contiene tu conversación y tus credenciales. Está oculto en el menú.

      Mejor uso: Informa de un consumo de memoria descontrolado.

      /release-notes

      Muestra el registro de cambios en un selector de versiones; las notas aparecen sin entrar en el contexto de Claude.

      Mejor uso: Mira qué hay de nuevo después de una actualización.

      /restart

      Reinicia Claude Code y retoma la sesión para aplicar una actualización instalada. Requiere Pro, Max o Ultra y una instalación nativa en macOS o Linux (no WSL).

      Mejor uso: Cuando la barra inferior lo ofrece tras una actualización.
