/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

Buscar errores antes del commit y, si quieres, corregirlos

Inglés code review ＝ revisión de código

★ Empieza aquíHabilidad¥ Puede costar dinero↗ Envía datos fuera⇄ Cambios amplios en archivos

Revisa el diff actual, o un PR, una rama o una ruta, en busca de errores de funcionamiento. --fix aplica las correcciones, --comment publica en el PR de GitHub o el MR de GitLab, ultra hace una revisión profunda en la nube.

Mejor uso

Antes de hacer commit: /code-review high --fix. Para un PR: /code-review high 1234.

Alias

/review

Etiquetas de seguridad

¥ Puede costar dinero: Puede consumir uso de pago o generar cargos extra. Revisa primero /usage y los precios oficiales.

↗ Envía datos fuera: Envía la conversación, el código o comentarios a otro servicio (Anthropic, GitHub, sesiones en la nube, sitios abiertos en tu navegador) o hace push a un remoto. Comprueba primero qué se envía y adónde.

⇄ Cambios amplios en archivos: Puede cambiar o revertir muchos archivos a la vez. Haz commit o una copia de seguridad antes, y revisa con /diff después.

Cuándo usarlo

  • Revisar el trabajo antes de hacer commit o de publicarlo/diff → /code-review → /security-review → /verify

Comandos relacionados · Revisión y verificación

  • /runInicia y maneja la aplicación de tu proyecto para ver un cambio funcionando.
  • /run-skill-generatorEscribe una habilidad propia del proyecto que enseña a /run y /verify a compilar, iniciar y manejar tu aplicación desde un entorno limpio.
  • /security-reviewAnaliza el diff de tu rama frente a la rama predeterminada de origin en busca de vulnerabilidades como inyección, problemas de autenticación o exposición de datos.
  • /simplifyCuatro agentes en paralelo revisan el código cambiado buscando reutilización, simplificación, eficiencia y nivel de abstracción, y luego aplican las correcciones.
  • /ultrareviewRevisión profunda con varios agentes en un sandbox en la nube.
  • /verifyCompila, ejecuta y observa tu aplicación para confirmar que un cambio funciona, en lugar de fiarse de las pruebas o de la comprobación de tipos.
