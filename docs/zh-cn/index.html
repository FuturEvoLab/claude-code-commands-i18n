/Claude Code 命令大全

Claude Code 里所有以 / 开头的命令，用简单中文逐条讲清楚：英文原意、能做什么、什么时候用最合适。

claude
❯

    按场景找命令

    选你想做的事，命令按建议尝试的顺序排列。

    • Claude 改坏了，我想撤销: /rewind /diff
    • 换一件不相关的事，从头开始: /clear /resume
    • 对话太长，Claude 变慢或开始忘事: /context /compact /autocompact
    • 接着做昨天没做完的: /resume /rename /recap
    • 大改动前，想先看方案再让它动手: /plan /effort /model
    • 让 Claude 一直用中文回答: /init /memory
    • 省钱、省额度: /usage /model /effort /context
    • 提交或上线前做检查: /diff /code-review /security-review /verify
    • 同时做几件事 / 放后台跑: /fork /subtask /background /tasks /batch
    • 让它反复做或定时做: /loop /schedule /goal
    • 权限确认弹窗太多: /permissions /fewer-permission-prompts
    • 连接外部工具或安装新能力: /mcp /plugin /skills
    • 做幻灯片、设计稿或图表: /slides /design /dataviz /artifacts
    • 离开电脑，用手机继续: /remote-control /mobile /desktop
    • Claude Code 本身出问题了: /doctor /status /debug /bug
    • 系统学习怎么用: /powerup /help /insights

    安全标记

    带这些标记的命令请格外小心。

      对话与上下文

      新开、压缩、撤销、找回对话，管理 Claude 的「记忆空间」

      /clear [name]

      开始一个上下文为空的新对话。项目记忆（CLAUDE.md）仍然有效。旧对话不会删除，可以用 /resume 找回；写上名字可以给旧对话加标签。

      最佳用法: 做完一个功能、要开始一件无关的新任务时：/clear 登录功能。避免旧内容干扰，也更省用量。

      /compact [instructions]

      把到目前为止的对话总结成摘要，腾出上下文空间，对话继续。可以附上「摘要要重点保留什么」。

      最佳用法: 长时间对话后：/compact 保留数据库结构和尚未修复的 bug 列表。

      /context [all]

      用彩色方格图显示上下文用了多少、被什么占用，并给出节省建议和容量警告。all 展开全部明细。

      最佳用法: 感觉 Claude 变「健忘」或用量涨得快时，先 /context 看是不是被大文件或工具输出占满。

      /plan [description]

      直接进入计划模式：Claude 先调查并提出方案，你批准后才开始修改文件。可附上任务描述立即开始。

      最佳用法: 大改动之前：/plan 修复登录报错，看完方案再放手让它改。

      /resume [session]

      按 ID 或名字恢复以前的对话，不写参数则打开对话列表。后台会话会标记为 bg。

      最佳用法: 昨天没做完就关了电脑：今天 /resume，选昨天的对话接着做。

      /rewind

      把对话和/或代码退回到之前的某个检查点，或者从选中的消息开始做摘要。类似游戏「读档」。

      最佳用法: Claude 把文件改坏了：/rewind，选择改动之前的那条消息，代码和对话一起恢复。

      /autocompact [auto|<tokens>]

      设置上下文用到多满时自动压缩，例如 500k；auto 恢复为模型默认值。保存到用户设置并立即生效。

      最佳用法: 长任务不想被频繁压缩打断：/autocompact 500k。

      /branch [name]

      在当前位置为对话建一个分支并切换过去，用来尝试另一个方向；原对话保留，可用 /resume 回去。（这是对话分支，不是 Git 分支。）

      最佳用法: 方案 A 和 B 拿不准：/branch 试方案B，不行就回到原对话继续 A。

      /btw [question]

      就当前会话问一个旁支问题，答案不会加入对话历史。不带问题则显示最近一次旁支问答。

      最佳用法: Claude 正在写代码，你想知道一个报错的意思：/btw 这个 404 是什么意思，不打乱主任务。

      /copy [N]

      把最近一条回答复制到剪贴板；/copy 2 复制倒数第二条。有代码块时会弹出选择器，可只复制某一块；按 w 写入文件（SSH 远程时有用）。

      最佳用法: Claude 写好一段文案或命令，/copy 直接粘贴到别处。

      /export [filename]

      把当前对话导出为纯文本。写文件名则直接保存，不写则弹出「复制或保存」对话框。

      最佳用法: 一次很有价值的排错过程：/export 排错记录.txt 存档或发给同事。

      /goal [condition|clear]

      设定一个完成条件，Claude 会跨多轮持续工作，直到条件满足或目标被清除。不带参数显示当前目标；clear、stop、off 等可提前取消。

      最佳用法: /goal 所有测试都通过，然后让它自己一轮轮修，直到全绿。

      /memory

      编辑 CLAUDE.md 记忆文件，开关「自动记忆」，查看自动记住的条目。

      最佳用法: 想让 Claude 每次都用中文回答：/memory 打开 CLAUDE.md，写入「请始终用简体中文回答」。

      /recap

      立即生成当前会话的一句话总结。

      最佳用法: 开完会回来忘了做到哪：/recap。

      /rename [name]

      给当前会话改名，并显示在输入栏上方。不写名字则根据对话内容自动生成。

      最佳用法: 同时开着多个会话时：/rename 量化回测，之后在 /resume 里一眼认出。

      模型与推理

      换模型、调思考力度、调速度

      /model [model]

      切换 AI 模型，并保存为新会话的默认模型。不带参数打开选择器；支持的模型可用左右方向键调思考力度；在某一行按 s 只对当前会话生效。

      最佳用法: 简单改文案用较快较省的模型；遇到难 bug 时 /model opus 换更强的模型。

      /advisor [model|off]

      开关「顾问工具」：任务关键时刻请第二个模型提供建议。可填 fable、opus、sonnet 或完整模型 ID（fable 需要相应权限）。不带参数打开选择器。

      最佳用法: 平时用较快的模型干活，又怕关键决策出错：/advisor opus。

      /effort [level|auto|status|ultracode [on|off]]

      设置思考力度：low 到 xhigh、max 或 auto；status 显示当前值。max 只对当前会话有效。ultracode on|off 开关 ultracode 模式。

      最佳用法: 排查难以复现的 bug：/effort high；只是改错别字：/effort low。

      /fast [on|off]

      开关快速模式（同一个模型，输出更快）。在 Claude 回复中途也能切换，但正在进行的这一轮仍按原速度完成。计费方式请以官方 fast mode 说明为准。

      最佳用法: 赶时间需要大量生成时 /fast on，不急时 /fast off。

      /output-style [style]

      列出或切换输出风格（回答的写法），例如 /output-style concise。

      最佳用法: 先不带参数运行 /output-style 看有哪些风格，再选一个适合你的（例如更简洁的）。

      项目与文件

      让 Claude 认识你的项目、访问文件夹、查看改动

      /init

      读取项目并生成 CLAUDE.md「项目说明书」，之后每次新对话都会先读它。如果发现 Codex 或 Gemini CLI 的配置，会提议用 /import 迁移。

      最佳用法: 接手新项目时第一件事：/init，然后用 /memory 补充「请用中文回答」等个人要求。

      /add-dir <path>

      本次会话额外允许访问另一个文件夹，当前工作位置不变。输入部分路径会提示补全，按 Tab 接受。被添加文件夹里的大部分 .claude/ 配置不会被读取；多数网络路径不能添加。

      最佳用法: 前端和后端分在两个文件夹：/add-dir ../backend，让它同时看两边。

      /cd <path>

      把当前会话移到另一个工作文件夹，对话保留。和 /add-dir 的区别：/cd 是搬家，/add-dir 是多开一扇门。

      最佳用法: 在错误的文件夹里开始了对话：/cd ~/projects/website，不用重来。

      /diff

      查看工作区的改动，包括 Claude 目前做的修改。

      最佳用法: Claude 说「改好了」后，提交前先 /diff 亲眼确认改了什么。

      /import [codex|gemini|cursor] [--dry-run] [--yes]

      把本机 OpenAI Codex、Google Gemini CLI 或 Cursor 的配置（说明文件、MCP 服务器、命令、子代理、技能）导入 Claude Code。--dry-run 只预览不写入。部分云平台不可用；从 Cursor 导入需 v2.1.265+。

      最佳用法: 从 Cursor 转过来：先 /import cursor --dry-run 看会导入什么，没问题再正式导入。

      /insights

      生成一份 HTML 报告，分析你在本机的近期使用：常用项目、使用方式、容易出错的地方、值得尝试的功能。云端会话中不可用。

      最佳用法: 用了一段时间后 /insights，发现自己从没用过的好功能。

      /team-onboarding

      分析你过去 30 天的会话、命令和 MCP 使用情况，生成一份 Markdown 入门指南，新同事可以直接作为第一条消息粘贴。

      最佳用法: 团队来了新人：/team-onboarding，把生成的指南发给 TA。

      审查与验证

      找 bug、找安全漏洞、清理代码、实际运行验证

      /code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

      检查当前改动（或指定的 PR、分支、路径）有没有正确性 bug。可选力度；--fix 让 Claude 直接修，--comment 发到 GitHub PR 或 GitLab MR；ultra 在云端做深度审查。

      最佳用法: 提交前：/code-review high --fix，找出问题并顺手修好。审查别人的 PR：/code-review high 1234。

      /run

      启动并操作你的项目应用，看改动的实际效果。

      最佳用法: /run，让它启动网站并截图新首页给你看。

      /run-skill-generator

      为本项目写一个专属技能，教会 /run 和 /verify 如何从干净环境构建、启动和操作你的应用。

      最佳用法: 项目启动步骤复杂（要先起数据库等），跑一次，以后 /run 一步到位。

      /security-review

      对比当前分支与远程默认分支的差异，找出安全隐患，如注入、认证问题、数据泄露。需要名为 origin 的远程仓库。

      最佳用法: 涉及登录、支付、用户数据的改动上线前跑一次。

      /simplify [target]

      4 个审查代理并行检查改动：能否复用现有代码、能否更简单、效率、抽象层级是否合适，并直接改好。不查正确性 bug（那是 /code-review 的事）。

      最佳用法: 功能已经能跑，想让代码更好维护：/simplify。

      /ultrareview [PR or branch]

      在云端沙箱里用多个代理深度审查代码。推荐写法是 /code-review ultra，/ultrareview 是别名。Pro、Max、Ultra 含 3 次免费，之后需要用量额度。

      最佳用法: 重要版本发布前：/code-review ultra。

      /verify

      真正构建并运行你的应用、观察结果，确认改动有效，而不是只看测试或类型检查。只在你手动调用时运行。

      最佳用法: 改了按钮逻辑：/verify，让它亲自打开应用点一下。

      并行与后台

      同时让多个 Claude 干活，或放到后台运行

      /agents

      新版本中只显示一条提示：直接让 Claude 创建或管理子代理，或编辑 .claude/agents/ 文件夹。v2.1.197 及更早版本会打开管理界面。

      最佳用法: 直接说：「帮我建一个专门写测试的子代理」。

      /background [prompt]

      把当前会话转为后台代理继续运行，释放终端。可附带最后一条指令。用 claude agents 查看。

      最佳用法: 一个要跑半小时的整理任务：/bg 完成后把结果写进 report.md。

      /batch <instruction>

      大规模并行改代码：先研究代码库，把工作拆成 5～30 个独立单元并给出计划；你批准后，每个单元由一个后台子代理在独立 worktree 中实现、测试并提交。需要 Git 仓库（或相应 hook）。

      最佳用法: /batch 把 src/ 从 JavaScript 迁移到 TypeScript。

      /fork [prompt]

      把当前对话复制成一个新的后台会话，这边继续工作。带上指令则副本立即开始。副本一般会先创建自己的 worktree 再改代码。

      最佳用法: 正在做功能 A，想同时修一个小问题：/fork 修复页脚错位。

      /list-agents

      列出 Claude 可以发消息的子代理、团队成员和其他会话，以及各自的名字。仅在启用跨会话消息时可用。

      最佳用法: 多个会话协作时，确认彼此的名字。

      /stop

      停止你当前连接的后台会话，记录和 worktree 保留。只想断开不停止，用 /exit 或按 ←。

      最佳用法: 后台任务方向跑偏：/stop。

      /subtask <task>

      派出一个继承完整对话的后台子代理去做任务，完成后结果回到当前对话。与 /fork 的区别：/subtask 的结果会汇报回来，/fork 是独立的会话。

      最佳用法: /subtask 为这些接口写 API 文档，你这边继续写代码。

      /tasks

      查看和管理当前会话的后台工作，包括已完成的子代理。

      最佳用法: 后台跑着测试或子代理时，用 /tasks 看进度。

      /workflow-authoring

      加载编写动态工作流脚本的参考资料。Claude 一般会自动加载；手动修改已保存脚本前可以自己运行。仅在启用动态工作流时可用。

      最佳用法: 想手动调整一个保存的工作流脚本前。

      /workflows

      打开工作流进度视图，查看、暂停、继续、保存正在运行或已完成的多代理工作流。

      最佳用法: 跑大型研究或改造工作流时，用它盯进度。

      定时与自动化

      让它按间隔反复做、按时间表做、自动修 PR

      /loop [interval] [prompt]

      在会话开着时反复执行一条指令。不写间隔则由 Claude 自己掌握节奏；不写指令则运行内置维护提示或你的 loop.md。关闭会话就停止。

      最佳用法: /loop 5m 检查部署是否完成。需要电脑关机也执行的话用 /schedule。

      /autofix-pr [prompt]

      开一个云端会话盯住当前分支的 PR，CI 失败或有人留评审意见时自动推送修复。需要 gh 命令行工具和云端会话权限。

      最佳用法: 只想让它修格式问题：/autofix-pr 只修 lint 和类型错误。

      /deep-research <question>

      多代理工作流：大量搜索网页、抓取并交叉核对来源，写成带引用的报告。在后台运行。

      最佳用法: /deep-research 主流 AI 视频生成工具的价格与画质对比。

      /schedule [description]

      创建、修改、列出或运行云端定时任务（以前叫 routines），通过对话引导设置，也可以问最近的运行记录。使用 Console API 密钥时不可用。

      最佳用法: /schedule 每个工作日早上 9 点检查仓库新 issue 并总结。

      网页、幻灯片与设计

      产出可以分享的网页、演示文稿、设计稿和图表

      /artifact-capabilities

      加载 artifact 运行时可用能力的参考，例如调用你的连接器、给访客提供文件下载，以及你的账号有哪些。Claude 一般会自动加载。

      最佳用法: 打算做一个多人填写的报名表页面之前。

      /artifact-diagramming

      加载在 artifact 中画示意图的规范：何时需要图、画什么、如何写出在浅色和深色主题下都清楚的 SVG。

      最佳用法: 需要一张清楚的系统流程图时。

      /artifacts

      列出你拥有或别人分享给你的 artifact（网页成品），可以接入当前会话、在浏览器打开或复制链接。仅在支持 artifact 的环境可用。

      最佳用法: 找回上周做的那个仪表盘页面，接着修改。

      /dataviz [request]

      图表设计指南：为数据选择合适的图表形式、按用途配色，用自带脚本检查色盲友好和对比度。

      最佳用法: /dataviz 把这份月度销售表做成趋势图。

      /design [brief]

      在一张画布上绘制界面草图、页面流程、落地页或海报（Claude Design artifact），可在桌面浏览器编辑并导出 PNG 或 PDF。Bedrock、Vertex 等第三方平台不可用。

      最佳用法: /design 手机记账 App 的设置页。

      /design consent

      授予或撤销 Claude 对 Claude Design 的访问权限。当 Claude 的回复要求你运行 /design consent 时，需要你自己在输入框中输入。

      最佳用法: Claude 提示需要授权时，手动输入 /design consent。

      /design-login

      为 /design-sync 用 claude.ai 账号授权。当 /design-sync 或 /design consent 提示时使用。

      最佳用法: /design-sync 提示需要登录时运行。

      /design-sync [hint]

      把仓库中的 React 设计系统转换并上传到 Claude Design，让生成的设计使用你真实的组件。首次同步会逐个验证组件，大仓库可能要几个小时。上传目标是独立的 claude.ai/design 网站，该网站将于 2026 年 12 月 14 日前关闭。

      最佳用法: 公司有自己的组件库：/design-sync Acme DS。注意上述关闭日期。

      /slides [brief]

      根据你的描述生成一套 Claude Slides 演示文稿（artifact）。需要支持 artifact 的会话和可用的 Slides 模板。

      最佳用法: /slides 季度业绩回顾，8 页，面向管理层。

      插件、技能与外部连接

      给 Claude 装新能力：插件、技能、MCP 连接器、浏览器、编辑器

      /mcp [reconnect (<server>|all)|enable|disable [<server>|all]]

      管理 MCP 服务器连接和 OAuth 登录。不带参数打开列表；reconnect、enable、disable 加服务器名或 all 可直接操作。

      最佳用法: 连接器报错或需要登录：/mcp reconnect all。

      /chrome

      配置 Claude in Chrome 的设置。

      最佳用法: 第一次连接 Chrome 扩展时。

      /claude-api [subcommand]

      加载与你项目语言对应的 Claude API 和 Managed Agents 资料；代码导入 anthropic 时会自动启用。子命令包括 migrate、upgrade、api-version、cost-optimize、latency-optimize、build-eval、prompt-audit 等。

      最佳用法: 自己开发 AI 应用、想降低 API 费用：/claude-api cost-optimize。

      /claude-in-chrome [task]

      通过 Claude in Chrome 扩展让 Claude 在你的浏览器里执行任务，如测试页面、填写表单、读取控制台日志。需启用 Chrome 集成（如 claude --chrome）。

      最佳用法: /claude-in-chrome 打开本地网站，测试注册流程并报告错误。

      /ide

      管理与 VS Code、JetBrains 等编辑器的集成并显示状态。

      最佳用法: 编辑器里看不到 Claude 的改动时，检查是否连上。

      /install-github-app

      为仓库安装 Claude GitHub App，可选设置 GitHub Actions 工作流和密钥。仅适用于 github.com 仓库。

      最佳用法: 希望在 GitHub 的 issue 或 PR 中 @claude 让它干活。

      /install-slack-app

      安装 Claude Slack 应用，会打开浏览器完成 OAuth 授权。

      最佳用法: 团队想在 Slack 里直接叫 Claude。

      /plugin [subcommand]

      管理插件（一包命令、技能、代理、工具）。不带参数打开菜单，或用 list、install、enable、disable 直接操作。安装后若提示，需要 /reload-plugins。

      最佳用法: /plugin 浏览插件市场，装一个适合你工作的插件。

      /plugin-authoring

      加载编写「mod」（修改 Claude 界面或行为的小扩展）的参考资料。来自内置插件，可在 /plugin 中关闭。

      最佳用法: 想做一个常驻侧边栏的小面板时。

      /reload-plugins [--force]

      不重启就应用插件改动，并报告加载数量和错误。如果会改变已加载的 MCP 工具（导致提示缓存失效），会警告并跳过，除非加 --force。

      最佳用法: 刚装完插件、提示需要重新加载时。

      /reload-skills

      重新扫描技能和命令文件夹，让会话中新增或修改的技能立即可用，并报告增减数量。

      最佳用法: 刚写好一个自定义技能文件，不重启就想用。

      /skill-doctor

      显示每个技能占用多少上下文、使用频率如何，帮你找出可以关闭的技能。

      最佳用法: 定期体检，清理长期不用的技能。

      /skills

      列出可用技能，可按名称、描述、来源筛选；按 t 按占用 token 排序；Space/Enter 切换技能对 Claude 和 / 菜单是否可见；Esc 保存关闭。

      最佳用法: 技能太多占空间：/skills 按 t 排序，隐藏用不到的。

      权限与安全

      控制 Claude 能做什么、什么要先问你

      /permissions

      管理工具权限的「允许 / 询问 / 禁止」规则：按范围查看、增删规则、管理工作目录，查看「Recently blocked」标签页（自动模式拦下的操作）和分类规则。

      最佳用法: 每次都被问「能否运行 npm test」很烦：在这里把它设为允许。

      /auto-mode-setup

      根据你的项目和近期会话起草 autoMode.environment 条目，审核后保存到用户设置，帮助自动模式更准确地判断。有版本和套餐要求。

      最佳用法: 自动模式总是误拦你常用的操作时。

      /fewer-permission-prompts

      扫描历史记录中常用的只读 Bash 和 MCP 调用，把它们按优先级加入项目 .claude/settings.json 的允许清单。

      最佳用法: 被权限确认打断太多次时跑一次。

      /hooks

      查看 hook 配置。

      最佳用法: 怀疑某个 hook 导致每次编辑都报错时，先看看配置了什么。

      /privacy-settings

      查看和修改隐私设置，仅限 Pro、Max、Ultra 订阅用户。

      最佳用法: 想确认自己的数据使用设置时。

      /sandbox

      开关沙箱模式，仅在支持的平台上可用。

      最佳用法: 要运行来源不太熟悉的脚本时先开启。

      /update-config [request]

      用自然语言描述设置改动（允许某命令、设置环境变量、添加 hook），Claude 修改对应的 settings.json。主题、模型等用 /config。

      最佳用法: /update-config 每次编辑文件后自动运行 prettier。

      设置与界面

      主题、颜色、状态栏、快捷键、语音输入

      /color [color|default]

      设置当前会话输入栏的颜色：red、blue、green、yellow、purple、orange、pink、cyan；default 恢复；不带参数随机。

      最佳用法: 操作生产环境的会话设成 /color red，时刻提醒自己小心。

      /config [key=value ...]

      打开设置界面（主题、模型、输出风格等）。也可直接写 key=value 修改，例如 /config theme=dark。/config --help 列出可用的键。

      最佳用法: /config theme=dark，一步切换深色主题。

      /focus

      切换专注视图：只显示你的最后一条提问、一行工具调用摘要和最终回答。仅全屏渲染模式可用。

      最佳用法: 不想看大量中间过程，只看结论。

      /keybindings

      打开快捷键配置文件。

      最佳用法: 把常用操作改成你习惯的按键。

      /scroll-speed

      交互式调整鼠标滚轮速度。仅全屏渲染模式可用，JetBrains 终端中不可用。

      最佳用法: 滚一下跳太多行时调慢。

      /statusline

      配置底部状态栏。用文字描述想显示的内容，或不带参数从你的 shell 提示符自动配置。

      最佳用法: /statusline 显示当前模型和 git 分支。

      /terminal-setup

      在 VS Code、Cursor、Devin Desktop、Alacritty、Zed 中安装 Shift+Enter 换行；Apple 终端改为 Option+Enter 并关闭提示音；iTerm2 中开启剪贴板权限让 /copy 可用。

      最佳用法: 一按回车就把没写完的需求发出去了？跑一次它。

      /theme

      更换配色主题：auto 跟随终端、浅色/深色、色觉友好主题、ANSI 主题和自定义主题。

      最佳用法: 晚上看屏幕累，换深色主题。

      /tui [default|fullscreen]

      设置终端界面渲染方式并保留对话重新启动。fullscreen 为不闪烁的全屏模式；不带参数显示当前方式。

      最佳用法: 终端画面闪烁时：/tui fullscreen。

      /voice [hold|tap|off]

      开关语音输入，或指定模式：hold 按住说话、tap 点按开始。需要 Claude.ai 账号。

      最佳用法: 打字慢、英文键盘不熟时，直接说中文下指令。

      账号与用量

      登录、查额度、看费用、升级套餐

      /usage

      显示本次会话费用、今天 / 本周 / 本月的花费、套餐用量上限和活动统计。订阅套餐会显示哪些消耗计入套餐上限。/stats 打开统计标签页。每条警告都会写明原因和一句话的解决办法，按 f 即可应用这些修复。

      最佳用法: 担心额度不够时 /usage 看一眼，再决定是否换较省的模型。

      /login

      登录 Anthropic 账号。

      最佳用法: 换电脑或登录过期时。

      /logout

      退出 Anthropic 账号。

      最佳用法: 在共用电脑上用完后。

      /passes

      把一周免费 Claude Code 分享给朋友。仅在账号符合条件时显示。

      最佳用法: 推荐朋友试用。

      /rate-limit-options

      claude.ai 用量上限阻止请求时显示选项：等待重置后自动继续、添加用量额度或升级套餐。需要 claude.ai 订阅。

      最佳用法: 深夜跑任务被限额卡住：选择「重置后自动继续」，第二天醒来已完成。

      /status

      打开设置的「状态」页：版本、模型、账号、连接情况。Claude 回复中也能运行。

      最佳用法: 向别人求助前先截一张 /status 的图。

      /upgrade

      在浏览器打开升级套餐的页面。

      最佳用法: 额度经常不够用时。

      /usage-credits

      达到上限时配置或申请用量额度：打开账单设置页；Team/Enterprise 无账单权限的成员则向管理员发送申请。旧名 /extra-usage。

      最佳用法: 团队账号用完额度，向管理员申请。

      云端、远程与其他设备

      在桌面 App、手机、网页、云端之间接力

      /desktop

      在 Claude Code 桌面 App 中继续当前会话。需要 macOS 或 x64 Windows 及 Claude 订阅。

      最佳用法: 终端里聊着想换成有图形界面的 App。

      /mobile

      显示下载 Claude 手机 App 的二维码。

      最佳用法: 想在手机上查看进度或远程操作。

      /remote-control

      让本会话可以从 claude.ai（网页或手机）远程操作。需要 claude.ai 订阅。

      最佳用法: 电脑上开着任务出门，用手机继续指挥：/rc。

      /remote-env

      选择从命令行启动云端会话时默认使用的云端环境。

      最佳用法: 有多个云端环境时设一个默认值。

      /setup-bedrock

      通过向导配置 Amazon Bedrock 的认证、区域和模型。设置 CLAUDE_CODE_USE_BEDROCK=1 之前不会出现在菜单中，需要完整输入。

      最佳用法: 公司通过 AWS 使用 Claude 时。

      /setup-vertex

      通过向导配置 Google Cloud Agent Platform 的认证、项目、区域和模型。设置 CLAUDE_CODE_USE_VERTEX=1 之前不会出现在菜单中，需要完整输入。

      最佳用法: 公司通过 Google Cloud 使用 Claude 时。

      /teleport

      把云端会话拉到本地终端：选择后获取分支和对话。需要 claude.ai 订阅。

      最佳用法: 在网页版开始的任务，拉回本地继续。

      /web-setup

      用本地 gh 命令行的登录信息，为云端会话连接 GitHub 账号。

      最佳用法: 第一次使用云端会话前。

      诊断与反馈

      出问题时先看这里

      /doctor [prompt-audit [path]]

      体检：诊断安装、设置、扩展和 CLAUDE.md 的问题并提出修复方案，你确认后 Claude 才会修改。prompt-audit 改为审查你的说明文件。

      最佳用法: Claude Code 出现莫名其妙的问题时，第一步 /doctor。

      /help

      显示帮助和可用命令。

      最佳用法: 忘了命令名时先打 /help，或打 / 加几个字母筛选。

      /powerup

      通过带动画演示的互动小课程学习 Claude Code 的功能。

      最佳用法: 新手系统学习的最佳入口。

      /bug [report]

      报告 bug 或分享对话。你可以选择附带多少会话记录，并在同意页面确认后才会发送。

      最佳用法: 遇到明显是 Claude Code 本身的故障时。

      /debug [description]

      为当前会话开启调试日志，并通过阅读日志排查问题。从运行时刻开始记录；可附上问题描述。

      最佳用法: /debug MCP 服务器一直连不上。

      /exit

      退出命令行。在已连接的后台会话中，它只是断开，会话继续运行。

      最佳用法: 今天收工。

      /feedback [report]

      发送产品反馈，使用与 /bug 相同的对话框和同意步骤。

      最佳用法: 想要某个新功能时告诉官方。

      /heapdump

      把 JavaScript 内存快照和内存明细写到桌面，用于排查内存占用过高。报告问题时只附 -diagnostics.json；.heapsnapshot 含完整对话和凭据，不要分享。菜单中隐藏，需完整输入。

      最佳用法: Claude Code 占用好几 GB 内存时，用于向官方报告。

      /release-notes

      在版本选择器中查看更新日志。内容显示在记录里，但不会进入 Claude 的上下文。

      最佳用法: 升级后看看有什么新功能。

      /restart

      重启 Claude Code 并恢复当前会话，以应用已安装的更新。需要 Pro、Max 或 Ultra，以及 macOS/Linux 的原生安装（不支持 WSL）。

      最佳用法: 底部提示更新已安装时运行。
