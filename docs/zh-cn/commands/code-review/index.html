/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

提交前检查 bug，可自动修复

英文 code review ＝ 代码审查

★ 新手推荐技能¥ 可能产生费用↗ 会发送到外部⇄ 会大范围修改文件

检查当前改动（或指定的 PR、分支、路径）有没有正确性 bug。可选力度；--fix 让 Claude 直接修，--comment 发到 GitHub PR 或 GitLab MR；ultra 在云端做深度审查。

最佳用法

提交前：/code-review high --fix，找出问题并顺手修好。审查别人的 PR：/code-review high 1234。

同义命令

/review

安全标记

¥ 可能产生费用: 可能消耗付费额度或产生额外费用。使用前用 /usage 确认额度，并查看官方价格说明。

↗ 会发送到外部: 会把对话、代码或评论发送到其他服务（如 Anthropic、GitHub、云端会话、浏览器中的网站），或推送到远程仓库。确认内容和目标后再运行。

⇄ 会大范围修改文件: 可能一次修改或还原很多文件。运行前先用 Git 提交或备份，运行后用 /diff 检查。

适用场景

  • 提交或上线前做检查/diff → /code-review → /security-review → /verify

相关命令 · 审查与验证

  • /run启动并操作你的项目应用，看改动的实际效果。
  • /run-skill-generator为本项目写一个专属技能，教会 /run 和 /verify 如何从干净环境构建、启动和操作你的应用。
  • /security-review对比当前分支与远程默认分支的差异，找出安全隐患，如注入、认证问题、数据泄露。需要名为 origin 的远程仓库。
  • /simplify4 个审查代理并行检查改动：能否复用现有代码、能否更简单、效率、抽象层级是否合适，并直接改好。不查正确性 bug（那是 /code-review 的事）。
  • /ultrareview在云端沙箱里用多个代理深度审查代码。推荐写法是 /code-review ultra，/ultrareview 是别名。Pro、Max、Ultra 含 3 次免费，之后需要用量额度。
  • /verify真正构建并运行你的应用、观察结果，确认改动有效，而不是只看测试或类型检查。只在你手动调用时运行。
