/Claude Code 指令大全

用淺顯的中文說明 Claude Code 的每一個斜線指令：英文原意、能做什麼，以及什麼時候最好用。

    依你想做的事找指令

    選一個情境；指令會依建議嘗試的順序列出。

    • Claude 把東西改壞了，我想復原: /rewind /diff
    • 從頭開始一件不相關的工作: /clear /resume
    • 對話太長，Claude 變慢或開始忘東忘西: /context /compact /autocompact
    • 繼續昨天沒做完的工作: /resume /rename /recap
    • 大幅修改前，先看計畫: /plan /effort /model
    • 讓 Claude 一律用中文回答: /init /memory
    • 省錢、省用量: /usage /model /effort /context
    • 提交或上線前先檢查: /diff /code-review /security-review /verify
    • 同時做好幾件事，或放到背景執行: /fork /subtask /background /tasks /batch
    • 重複執行或依排程執行工作: /loop /schedule /goal
    • 權限確認提示太多: /permissions /fewer-permission-prompts
    • 連接工具或增加新能力: /mcp /plugin /skills
    • 製作投影片、設計或圖表: /slides /design /dataviz /artifacts
    • 離開電腦，用手機繼續: /remote-control /mobile /desktop
    • Claude Code 本身運作異常: /doctor /status /debug /bug
    • 有系統地學會使用 Claude Code: /powerup /help /insights

    安全標記

    標有這些記號的指令，使用時請特別小心。

      對話與上下文

      開新對話、壓縮、倒帶、恢復對話；管理上下文視窗

      /clear [name]

      開始一個上下文為空的新對話，專案記憶仍然有效。舊對話會保留，可以用 /resume 重新開啟；加上名稱可以在清單中幫舊對話加標籤。

      最佳用法: 做完一個功能、要開始無關的新工作時：/clear 登入功能。舊內容不再干擾，用量也會減少。

      /compact [instructions]

      把目前為止的對話整理成摘要，騰出上下文空間，並在同一個對話中繼續。可以附上指示，決定摘要要保留哪些內容。

      最佳用法: 長時間對話之後：/compact 保留資料庫結構和尚未修正的 bug 清單。

      /context [all]

      用彩色方格圖顯示上下文的使用量，並提供最佳化建議和容量警告。all 會展開每一項的明細。

      最佳用法: 覺得 Claude 變健忘或用量增加很快時，執行 /context，看看是不是大型檔案或工具輸出佔滿了視窗。

      /plan [description]

      進入計畫模式：Claude 會先調查並提出計畫，再進行編輯。附上描述的話，會立刻開始處理那項工作。

      最佳用法: 大幅修改之前：/plan 修正登入驗證的 bug，看過計畫後再核准。

      /resume [session]

      用 ID 或名稱恢復之前的對話，或開啟工作階段清單。背景工作階段會標示為 bg。

      最佳用法: 昨天做到一半就闔上筆電：執行 /resume，選擇昨天的對話。

      /rewind

      把對話和（或）程式碼退回到之前的檢查點，或從選取的訊息開始做摘要。

      最佳用法: Claude 把好幾個檔案改壞了：執行 /rewind，選擇修改之前的那則訊息，把程式碼和對話一起還原。

      /autocompact [auto|<tokens>]

      設定上下文視窗用到多滿時自動壓縮，例如 500k；auto 會恢復成依模型調整的預設值。會儲存到使用者設定並立即生效。

      最佳用法: 長時間工作一直被壓縮打斷：/autocompact 500k。

      /branch [name]

      在目前位置為對話建立一個分支並切換過去；原本的對話會保留，可以用 /resume 回去。（這是對話分支，不是 Git 分支。）

      最佳用法: 兩種做法拿不定主意：/branch 試試方案B；如果不行，就回去繼續方案 A。

      /btw [question]

      針對目前的工作階段問一個旁支問題，不會加入對話紀錄。不加問題則顯示你最近一次的旁支問題。

      最佳用法: 工作進行中想弄懂一個錯誤：/btw 這個 404 是什麼意思，不會打亂主要工作。

      /copy [N]

      把最後一則回答複製到剪貼簿；/copy 2 複製倒數第二則。有程式碼區塊時，會出現選擇器讓你只複製其中一塊；按 w 改為寫入檔案（透過 SSH 連線時很有用）。

      最佳用法: Claude 寫好一段程式碼或指令：/copy，再貼到你需要的地方。

      /export [filename]

      把對話匯出為純文字。有給檔名就直接存成檔案，否則會開啟「複製或儲存」對話框。

      最佳用法: 把一次很有價值的除錯過程存檔：/export 除錯筆記.txt。

      /goal [condition|clear]

      設定目標：Claude 會跨多輪持續工作，直到條件達成或目標被清除。不加參數會顯示目前的目標；clear（或 stop、off 等）會移除目標。

      最佳用法: /goal 所有測試都通過，然後讓它反覆修改，直到測試全部通過。

      /memory

      編輯 CLAUDE.md 記憶檔案、開關自動記憶，並顯示自動記憶的項目。

      最佳用法: 希望每次都用中文回答：開啟 /memory，加上一行「請一律用繁體中文回答」。

      /recap

      隨時為目前的工作階段產生一句話的摘要。

      最佳用法: 開完會回來，忘了做到哪裡：/recap。

      /rename [name]

      替工作階段改名，並把名稱顯示在輸入列上；不給名稱則根據對話內容自動產生。

      最佳用法: 同時開著很多工作階段時：/rename 回測，在 /resume 裡一眼就能找到。

      模型與推理

      切換模型、調整思考力度和速度

      /model [model]

      切換模型，並儲存為新工作階段的預設值。不加參數會開啟選擇器；支援的模型可以用左右鍵調整思考力度；在某一列按 s 則只在這次工作階段切換。

      最佳用法: 小修改用比較快的模型；遇到難纏的 bug 時用 /model opus 切換。

      /advisor [model|off]

      開啟或關閉顧問工具，在關鍵時刻詢問第二個模型的意見。可以填 fable、opus、sonnet 或完整的模型 ID（fable 需要存取權限）。不加參數會開啟選擇器。

      最佳用法: 平常用較快的模型工作，但在關鍵決策時取得更強模型的第二意見：/advisor opus。

      /effort [level|auto|status|ultracode [on|off]]

      設定思考力度：low 到 xhigh、max 或 auto；status 會顯示目前的值。max 只在這次工作階段有效。ultracode on|off 可開關 ultracode。

      最佳用法: 追查時好時壞的 bug：/effort high；只是改錯字：/effort low。

      /fast [on|off]

      開關快速模式（同一個模型，輸出更快）。可以在回答途中切換，但正在進行的這一輪仍以原本的速度完成。價格請參考官方 fast mode 說明。

      最佳用法: 趕時間時：/fast on；其他時候：/fast off。

      /output-style [style]

      列出輸出風格或切換到其中一種，例如 /output-style concise。

      最佳用法: 先不加參數執行 /output-style，看看有哪些風格，再選一個（例如比較簡潔的風格）。

      專案與檔案

      設定專案記憶、新增資料夾、檢視修改

      /init

      為專案建立一份 CLAUDE.md 說明，之後每個新工作階段都會先讀它。如果發現 Codex 或 Gemini CLI 的設定，會建議使用 /import。

      最佳用法: 在新的儲存庫中第一件事：/init，然後用 /memory 補充調整。

      /add-dir <path>

      在這次工作階段中額外允許存取另一個工作資料夾，目前位置不會改變。輸入部分路徑後可以按 Tab 自動完成。新增的資料夾裡大部分的 .claude/ 設定不會被讀取，而且大多數網路路徑無法新增。

      最佳用法: 前端和後端放在相鄰的資料夾：/add-dir ../backend。

      /cd <path>

      把工作階段移到新的工作資料夾，對話會保留。和 /add-dir 不同，/cd 會改變工作階段所在的位置。

      最佳用法: 在錯誤的資料夾開始了：/cd ~/projects/website，不用從頭來過。

      /diff

      檢視工作目錄中的修改，包括 Claude 到目前為止做的編輯。

      最佳用法: 提交之前，用 /diff 確認到底改了什麼。

      /import [codex|gemini|cursor] [--dry-run] [--yes]

      從 OpenAI Codex、Gemini CLI 或 Cursor 匯入說明檔、MCP 伺服器、指令、子代理和技能。--dry-run 只預覽。部分雲端供應商無法使用；從 Cursor 匯入需要 v2.1.265+。

      最佳用法: 從 Cursor 轉過來：先執行 /import cursor --dry-run，再正式匯入。

      /insights

      為你在這台電腦上最近的工作階段產生一份 HTML 報告：專案、使用習慣、容易出問題的地方、值得嘗試的功能。雲端工作階段中無法使用。

      最佳用法: 用了幾週之後，執行 /insights，發現你從沒用過的功能。

      /team-onboarding

      分析你過去 30 天的工作階段、指令和 MCP 使用情況，寫出一份 Markdown 指南，讓同事可以貼上當作第一則訊息。

      最佳用法: 有新同事加入：執行 /team-onboarding，把指南傳給對方。

      審查與驗證

      找出 bug 和漏洞、整理程式碼、實際執行應用程式來驗證

      /code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

      檢查目前的修改（或指定的 PR、分支、路徑）有沒有正確性方面的 bug。--fix 會套用修正，--comment 會發布到 GitHub PR 或 GitLab MR，ultra 會在雲端進行深度審查。

      最佳用法: 提交之前：/code-review high --fix。審查 PR：/code-review high 1234。

      /run

      啟動並操作你專案的應用程式，看看修改實際運作的樣子。

      最佳用法: /run，啟動網站並截圖新的首頁。

      /run-skill-generator

      為這個專案寫一個專屬技能，教 /run 和 /verify 如何從乾淨的環境建置、啟動和操作你的應用程式。

      最佳用法: 啟動需要好幾個步驟（例如要先開資料庫）：執行一次這個指令，之後 /run 就能直接運作。

      /security-review

      比對你的分支與 origin 預設分支之間的差異，找出漏洞，例如注入、驗證問題和資料外洩。需要名為 origin 的遠端。

      最佳用法: 任何涉及登入驗證、付款或使用者資料的修改，上線前都跑一次。

      /simplify [target]

      4 個代理平行檢查修改過的程式碼：能否重複利用、能否更簡單、效率、抽象層級，然後直接套用修正。它不會找正確性的 bug；那要用 /code-review。

      最佳用法: 功能已經能正常運作，想讓程式碼更乾淨：/simplify。

      /ultrareview [PR or branch]

      在雲端沙箱中用多個代理深度審查。建議的寫法是 /code-review ultra；/ultrareview 是別名。Pro、Max 和 Ultra 包含 3 次免費執行，之後需要用量額度。

      最佳用法: 重大版本發布前：/code-review ultra。

      /verify

      實際建置、執行並觀察你的應用程式，確認修改有效，而不是只依賴測試或型別檢查。只有在你呼叫時才會執行。

      最佳用法: 改了按鈕的行為：/verify，讓它真的去點一下。

      平行與背景工作

      同時執行多個代理，或把工作移到背景

      /agents

      顯示一則提醒：請直接要求 Claude 建立或管理子代理，或直接編輯 .claude/agents/。在 v2.1.197 及更早的版本中，會開啟互動式管理介面。

      最佳用法: 直接說：「建立一個只負責寫測試的子代理。」

      /background [prompt]

      把工作階段轉為背景代理繼續執行，並釋放終端機。可以先再傳一條指示。用 claude agents 查看狀態。

      最佳用法: 需要 30 分鐘的工作：/bg 完成後把結果寫進 report.md。

      /batch <instruction>

      平行處理大規模修改：先研究程式碼，把工作拆成 5～30 個獨立單元並提出計畫；經你核准後，每個單元由一個背景子代理在自己的 worktree 中實作並測試。需要 git 儲存庫或 WorktreeCreate hook。

      最佳用法: /batch 把 src/ 從 JavaScript 遷移到 TypeScript。

      /fork [prompt]

      把對話複製成一個新的背景工作階段，你可以繼續在這裡工作。附上指示的話，副本會立刻開始；通常會先讓它建立自己的 worktree。

      最佳用法: 正在做功能 A，想同時修一個小問題：/fork 修正頁尾對齊。

      /list-agents

      列出 Claude 可以傳訊息的子代理、團隊成員和其他工作階段，以及各自要用的名稱。只在啟用跨工作階段訊息時可用。

      最佳用法: 協調多個工作階段時：確認每個工作階段的名稱。

      /stop

      停止你目前連接的背景工作階段；紀錄和 worktree 會保留。只想中斷連接而不停止，請用 /exit 或按 ←。

      最佳用法: 背景工作偏離方向：/stop。

      /subtask <task>

      派出一個分岔的子代理，它會繼承對話內容，並把結果回報到這裡。與 /fork 的差別：/subtask 會把結果回報到這裡，/fork 則會另開一個獨立的工作階段。

      最佳用法: /subtask 替這些 API 端點寫文件，你這邊繼續寫程式。

      /tasks

      檢視並管理這次工作階段中的背景工作，包括已完成的子代理。

      最佳用法: 用 /tasks 查看背景測試或子代理的進度。

      /workflow-authoring

      載入撰寫動態工作流程腳本的參考資料。Claude 通常會自己載入；手動編輯已儲存的腳本前可以先執行。只在啟用動態工作流程時可用。

      最佳用法: 手動編輯已儲存的工作流程腳本之前。

      /workflows

      開啟工作流程進度畫面，可以查看、暫停、繼續或儲存正在執行和已完成的工作流程。

      最佳用法: 隨時留意一個執行很久的工作流程。

      自動化與排程

      依間隔重複、依排程執行、自動修正 pull request

      /loop [interval] [prompt]

      在工作階段開著的期間反覆執行一個提示。不寫間隔則由 Claude 自己決定節奏；不寫提示則執行內建的維護提示或你的 loop.md。

      最佳用法: /loop 5m 檢查部署是否完成。如果要在電腦關機時也繼續執行，請用 /schedule。

      /autofix-pr [prompt]

      開啟一個雲端工作階段，盯著目前分支的 PR，在 CI 失敗或有審查意見時推送修正。需要 gh CLI 和雲端工作階段。

      最佳用法: /autofix-pr 只修 lint 和型別錯誤。

      /deep-research <question>

      內建的工作流程：大量搜尋網路、抓取並交叉比對來源，然後寫出附有引用的報告。在背景執行。

      最佳用法: /deep-research 比較主流 AI 影片工具的價格和品質。

      /schedule [description]

      透過引導式對話，建立、更新、列出或執行雲端排程工作（以前叫 routines）。使用 Console API 金鑰時無法使用。

      最佳用法: /schedule 每個工作日早上 9 點，整理儲存庫中新的 issue。

      網頁、投影片與設計

      製作可以分享的網頁、簡報、設計和圖表

      /artifact-capabilities

      載入 artifact 執行時功能的參考資料，例如呼叫連接器或提供下載，以及你的帳號有哪些功能。Claude 通常會自己載入。

      最佳用法: 要做一個很多人填寫的頁面之前。

      /artifact-diagramming

      載入在 artifact 中繪製圖表的指引：什麼時候圖有幫助、要畫什麼，以及如何寫出在淺色和深色主題下都清楚的 SVG。

      最佳用法: 需要一張清楚的架構圖時。

      /artifacts

      列出你擁有或別人分享給你的 artifact，然後可以接入其中一個、開啟它，或複製連結。只在支援 artifact 的環境中可用。

      最佳用法: 找到上週做的儀表板，繼續編輯。

      /dataviz [request]

      圖表設計指引：選擇圖表形式、依角色分配顏色，並用內建的腳本檢查配色是否色盲友善、對比是否足夠。

      最佳用法: /dataviz 把這份每月銷售表做成趨勢圖。

      /design [brief]

      在同一張畫布上以多個畫板草擬 UI 設計稿、操作流程、到達頁或海報（Claude Design artifact）；可在桌面瀏覽器中編輯，並匯出 PNG 或 PDF。Bedrock、Vertex 及其他第三方平台無法使用。

      最佳用法: /design 行動網銀 App 的設定畫面。

      /design consent

      授予或撤回 Claude 對 Claude Design 的存取權。當 Claude 要求你執行 /design consent 時，請自己輸入。

      最佳用法: 出現提示時，自己輸入 /design consent。

      /design-login

      當 /design-sync 或 /design consent 要求時，用你的 claude.ai 帳號為 /design-sync 授權設計系統存取。

      最佳用法: /design-sync 要求你登入時執行。

      /design-sync [hint]

      把你儲存庫中的 React 設計系統轉換並上傳到 Claude Design，讓設計使用你真正的元件。大型儲存庫第一次同步可能要好幾個小時。上傳目標是獨立的 claude.ai/design 網站，該網站將在 2026 年 12 月 14 日前關閉。

      最佳用法: /design-sync Acme DS（請注意上面提到的關閉日期）。

      /slides [brief]

      根據你的說明製作一份 Claude Slides artifact。需要支援 artifact 的工作階段，以及可以使用 Slides 範本的帳號。

      最佳用法: /slides 給主管看的季度回顧，8 張投影片。

      外掛、技能與整合

      用外掛、技能、MCP 伺服器、瀏覽器和 IDE 整合擴充 Claude

      /mcp [reconnect (<server>|all)|enable|disable [<server>|all]]

      管理 MCP 伺服器連線和 OAuth。不加參數會開啟清單；reconnect、enable 或 disable 加上伺服器名稱或 all 可直接操作。

      最佳用法: 連接器失敗或需要驗證：/mcp reconnect all。

      /chrome

      設定 Claude in Chrome。

      最佳用法: 第一次連接 Chrome 擴充功能時。

      /claude-api [subcommand]

      載入適合你專案程式語言的 Claude API 和 Managed Agents 參考資料；程式碼匯入 anthropic 時會自動啟用。子指令包括 migrate、upgrade、api-version、cost-optimize、latency-optimize、build-eval、prompt-audit、managed-agents-onboard、managed-agents-secure、hillclimb、preserved-thinking-migration。

      最佳用法: 降低你的應用程式的 API 花費：/claude-api cost-optimize。

      /claude-in-chrome [task]

      透過 Claude in Chrome 讓 Claude 在你的瀏覽器中執行工作，例如測試網頁或讀取主控台紀錄。需要啟用 Chrome 整合（例如 claude --chrome）。

      最佳用法: /claude-in-chrome 測試我本機網站的註冊流程並回報錯誤。

      /ide

      管理 IDE 整合並顯示狀態。

      最佳用法: 編輯器裡看不到修改時，檢查連線狀態。

      /install-github-app

      為儲存庫安裝 Claude GitHub App，也可以順便設定 GitHub Actions 工作流程和機密（secrets）。只適用於 github.com。

      最佳用法: 想在 issue 和 PR 中提及 Claude，讓它在那裡工作。

      /install-slack-app

      透過瀏覽器的 OAuth 流程安裝 Claude Slack 應用程式。

      最佳用法: 團隊想在 Slack 裡使用 Claude。

      /plugin [subcommand]

      管理外掛。不加參數會開啟選單；list、install、enable、disable 可直接操作。如果安裝摘要有提示，請執行 /reload-plugins。

      最佳用法: 用 /plugin 瀏覽，安裝一個適合你工作的外掛。

      /plugin-authoring

      載入撰寫 mod 的參考資料。這是內建外掛提供的技能，可以在 /plugin 中關閉。

      最佳用法: 想做一個固定在對話旁邊的小側邊面板時。

      /reload-plugins [--force]

      不必重新啟動就重新載入啟用中的外掛，並回報載入錯誤。如果重新載入會改變已載入的 MCP 工具、讓提示快取失效，它會發出警告並略過，除非你加上 --force。

      最佳用法: 剛裝好一個要求重新載入的外掛之後。

      /reload-skills

      重新掃描技能和指令資料夾，讓工作階段中新增或修改的技能不必重新啟動就能使用。

      最佳用法: 剛寫好一個自訂技能，想馬上使用。

      /skill-doctor

      顯示每個技能佔用的上下文和使用情況，幫你找出可以關閉的技能。

      最佳用法: 定期執行，清理沒在用的技能。

      /skills

      列出技能並可篩選。t 依 token 數排序，Space/Enter 切換技能對 Claude 和 / 選單是否可見，Esc 儲存並關閉。

      最佳用法: 技能太多：/skills，按 t，把佔空間又用不到的技能隱藏起來。

      權限與安全

      控制 Claude 可以做什麼、哪些事需要你核准

      /permissions

      管理工具的允許、詢問和拒絕規則：依範圍檢視、新增或移除規則、管理工作資料夾，查看「Recently blocked」分頁（自動模式擋下的操作）和分類器規則。

      最佳用法: 每次都要核准 npm test 很煩：在這裡把它設為允許。

      /auto-mode-setup

      根據你的專案和最近的工作階段，草擬 autoMode.environment 項目，讓你檢查後儲存。有版本和方案的限制。

      最佳用法: 自動模式一直擋下例行操作時。

      /fewer-permission-prompts

      掃描對話紀錄中常見的唯讀 Bash 和 MCP 呼叫，依優先順序把允許清單加到專案的 .claude/settings.json。

      最佳用法: 核准提示一直打斷你時，執行一次。

      /hooks

      檢視 hook 設定。

      最佳用法: 某個 hook 似乎讓每次編輯都出錯時，看看設定了什麼。

      /privacy-settings

      檢視和更新隱私設定。只限 Pro、Max 和 Ultra。

      最佳用法: 想確認你的資料如何被使用時。

      /sandbox

      開關沙箱模式，只在支援的平台上可用。

      最佳用法: 執行不熟悉的腳本之前先開啟。

      /update-config [request]

      描述你想要的設定變更（允許某個指令、設定環境變數、加入 hook），Claude 就會編輯對應的 settings.json。主題和模型請用 /config。

      最佳用法: /update-config 每次編輯檔案後執行 prettier。

      設定與介面

      主題、顏色、狀態列、快速鍵、語音

      /color [color|default]

      設定這次工作階段輸入列的顏色：red、blue、green、yellow、purple、orange、pink 或 cyan；default 恢復預設，不加參數則隨機選一個顏色。

      最佳用法: 用 /color red 標示正式環境的工作階段。

      /config [key=value ...]

      開啟設定畫面，調整主題、模型、輸出風格等，或直接設定 key=value，例如 /config theme=dark。/config --help 會列出可用的鍵。

      最佳用法: /config theme=dark。

      /focus

      切換一種只顯示你最後一則提示、一行工具摘要和最終回答的畫面。只限全螢幕渲染模式。

      最佳用法: 隱藏中間步驟，只看結果。

      /keybindings

      開啟你的快速鍵設定檔。

      最佳用法: 把操作改成你習慣的按鍵。

      /scroll-speed

      調整滑鼠滾輪的捲動速度。只限全螢幕渲染模式；JetBrains 終端機中無法使用。

      最佳用法: 滾一格就跳太遠時，把速度調慢。

      /statusline

      設定狀態列；描述你想顯示的內容，或不加參數，從你的 shell 提示字元自動產生。

      最佳用法: /statusline 顯示模型和 git 分支。

      /terminal-setup

      在 VS Code、Cursor、Devin Desktop、Alacritty 或 Zed 中設定 Shift+Enter 換行；在 Apple 終端機中啟用 Option+Enter 並關閉提示音；在 iTerm2 中開啟剪貼簿存取，讓 /copy 可以使用。

      最佳用法: 按 Enter 老是把寫到一半的提示送出去：執行一次這個指令。

      /theme

      更換配色主題：auto、淺色和深色、色盲友善、ANSI 和自訂主題。

      最佳用法: 晚上切換成深色主題。

      /tui [default|fullscreen]

      設定終端機的渲染方式，並在保留對話的情況下重新啟動。fullscreen 是不會閃爍的渲染方式。不加參數會顯示目前使用的渲染方式。

      最佳用法: 畫面閃爍時：/tui fullscreen。

      /voice [hold|tap|off]

      開關語音輸入，或設定模式（hold、tap）。需要 Claude.ai 帳號。

      最佳用法: 用說的下指示，不必打字。

      帳號與用量

      登入、查看上限和費用、升級

      /usage

      顯示這次工作階段的費用、今天／本週／本月的花費、方案用量上限和活動統計，包括訂閱方案中哪些項目會計入上限。/stats 會開啟統計分頁。每則警告都會寫明原因和一句話的解決方法，按 f 即可套用這些修正。

      最佳用法: 決定要不要換成比較便宜的模型之前，先看一下 /usage。

      /login

      登入你的 Anthropic 帳號。

      最佳用法: 換新電腦或登入過期時。

      /logout

      登出你的 Anthropic 帳號。

      最佳用法: 用完共用電腦之後。

      /passes

      和朋友分享一週免費的 Claude Code；只有符合資格的帳號才會顯示。

      最佳用法: 邀請朋友試用。

      /rate-limit-options

      當 claude.ai 的用量上限擋住你時，顯示可以繼續工作的方法：等待並自動繼續、加購用量額度，或升級。需要 claude.ai 訂閱。

      最佳用法: 半夜被上限擋住：選擇在重設後自動繼續。

      /status

      開啟設定的「狀態」分頁：版本、模型、帳號、連線狀況。Claude 正在回答時也能使用。

      最佳用法: 向別人求助之前，先截一張 /status 的畫面。

      /upgrade

      在瀏覽器中開啟升級頁面。

      最佳用法: 老是碰到用量上限時。

      /usage-credits

      設定或申請用量額度；沒有帳單權限的 Team 和 Enterprise 成員會向管理員送出申請。以前叫 /extra-usage。

      最佳用法: 團隊額度用完時，向管理員申請額度。

      雲端、遠端與其他裝置

      在桌面、手機、網頁和雲端之間接續工作

      /desktop

      在 Claude Code 桌面版 App 中繼續這次工作階段。需要 macOS 或 x64 Windows，以及 Claude 訂閱。

      最佳用法: 從終端機換到桌面版 App。

      /mobile

      顯示下載 Claude 手機 App 的 QR code。

      最佳用法: 想用手機跟上進度時。

      /remote-control

      讓這次工作階段可以從 claude.ai 進行遠端控制（Remote Control）。需要 claude.ai 訂閱。

      最佳用法: 讓工作繼續執行，用手機下指示：/rc。

      /remote-env

      選擇從 CLI 啟動雲端工作階段時預設使用的雲端環境。

      最佳用法: 有好幾個環境時，選一個當預設值。

      /setup-bedrock

      透過精靈設定 Amazon Bedrock 的驗證、區域和固定使用的模型。設定 CLAUDE_CODE_USE_BEDROCK=1 之前不會出現在選單中；需要完整輸入。

      最佳用法: 你的公司透過 AWS 使用 Claude 時。

      /setup-vertex

      透過精靈設定 Google Cloud 的 Agent Platform。設定 CLAUDE_CODE_USE_VERTEX=1 之前不會出現在選單中；需要完整輸入。

      最佳用法: 你的公司透過 Google Cloud 使用 Claude 時。

      /teleport

      把雲端工作階段拉到這個終端機，同時取得它的分支和對話。需要 claude.ai 訂閱。

      最佳用法: 在本機繼續從網頁版開始的工作。

      /web-setup

      用你本機的 gh 登入資訊，為雲端工作階段連接 GitHub。

      最佳用法: 第一次使用雲端工作階段之前。

      診斷與意見回饋

      出問題時先看這裡

      /doctor [prompt-audit [path]]

      為安裝、設定、擴充功能和 CLAUDE.md 做健檢，並提出修正方案，經你確認後由 Claude 套用。prompt-audit 則改為審查你的說明內容。

      最佳用法: 感覺哪裡怪怪的：先執行 /doctor。

      /help

      顯示說明和可用的指令。

      最佳用法: 忘了某個指令：/help，或輸入 / 加幾個字母。

      /powerup

      附有動畫示範的互動式課程，教你 Claude Code 的各種功能。

      最佳用法: 新手有系統地入門的最佳起點。

      /bug [report]

      回報 bug 或分享你的對話；你可以選擇要附上多少紀錄，而且在送出任何內容前都會請你確認。

      最佳用法: Claude Code 本身出現異常時。

      /debug [description]

      從現在開始啟用除錯紀錄，並透過閱讀工作階段的除錯紀錄來排查問題。可以附上問題描述。

      最佳用法: /debug MCP 伺服器一直連不上。

      /exit

      離開 CLI。在已連接的背景工作階段中，它只會中斷連接，工作階段會繼續執行。

      最佳用法: 今天的工作結束了。

      /feedback [report]

      用和 /bug 相同的對話框和同意步驟送出產品意見。

      最佳用法: 想要求新功能時。

      /heapdump

      把 heap 快照和記憶體明細寫到桌面，用來診斷記憶體用量過高的問題。只分享 -diagnostics.json；.heapsnapshot 含有你的對話和登入憑證。選單中不會顯示。

      最佳用法: 回報記憶體用量暴增的問題。

      /release-notes

      在版本選擇器中查看更新紀錄；內容會顯示出來，但不會進入 Claude 的上下文。

      最佳用法: 更新之後看看有什麼新功能。

      /restart

      重新啟動 Claude Code 並恢復工作階段，以套用已安裝的更新。需要 Pro、Max 或 Ultra，以及在 macOS 或 Linux 上的原生安裝（不支援 WSL）。

      最佳用法: 更新後底部出現提示時。
