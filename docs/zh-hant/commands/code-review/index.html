/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

提交前檢查 bug，也可以順便修正

英文 code review ＝ 程式碼審查

★ 新手推薦技能¥ 可能產生費用↗ 會傳送到外部⇄ 大範圍修改檔案

檢查目前的修改（或指定的 PR、分支、路徑）有沒有正確性方面的 bug。--fix 會套用修正，--comment 會發布到 GitHub PR 或 GitLab MR，ultra 會在雲端進行深度審查。

最佳用法

提交之前：/code-review high --fix。審查 PR：/code-review high 1234。

別名

/review

安全標記

¥ 可能產生費用: 可能消耗付費用量或產生額外費用。請先查看 /usage 和官方價格說明。

↗ 會傳送到外部: 會把對話、程式碼或留言傳送到其他服務（Anthropic、GitHub、雲端工作階段、你瀏覽器中的網站），或推送到遠端。請先確認什麼內容會送到哪裡。

⇄ 大範圍修改檔案: 可能一次修改或還原很多檔案。請先提交或備份，之後用 /diff 檢查。

適用情境

  • 提交或上線前先檢查/diff → /code-review → /security-review → /verify

相關指令 · 審查與驗證

  • /run啟動並操作你專案的應用程式，看看修改實際運作的樣子。
  • /run-skill-generator為這個專案寫一個專屬技能，教 /run 和 /verify 如何從乾淨的環境建置、啟動和操作你的應用程式。
  • /security-review比對你的分支與 origin 預設分支之間的差異，找出漏洞，例如注入、驗證問題和資料外洩。需要名為 origin 的遠端。
  • /simplify4 個代理平行檢查修改過的程式碼：能否重複利用、能否更簡單、效率、抽象層級，然後直接套用修正。它不會找正確性的 bug；那要用 /code-review。
  • /ultrareview在雲端沙箱中用多個代理深度審查。建議的寫法是 /code-review ultra；/ultrareview 是別名。Pro、Max 和 Ultra 包含 3 次免費執行，之後需要用量額度。
  • /verify實際建置、執行並觀察你的應用程式，確認修改有效，而不是只依賴測試或型別檢查。只有在你呼叫時才會執行。
