/bug[report]

英語 bug ＝ 不具合・バグ

↗ 外部に送信⚿ 機密情報を含む場合あり

不具合の報告や会話の共有をします。添付する履歴の量を選び、同意画面で確認してから送信されます。

おすすめの使い方

明らかに Claude Code 自体の不具合に出会ったとき。

別名

/share

安全マーク

↗ 外部に送信: 会話・コード・コメントを他のサービス（Anthropic、GitHub、クラウドセッション、ブラウザー上のサイトなど）に送ったり、リモートに push したりします。内容と送信先を確認してから実行してください。

⚿ 機密情報を含む場合あり: 作られるファイル・クリップボード・レポートに、会話内容・API キー・パスワード・個人情報が含まれる場合があります。共有する前に必ず確認し、該当する部分を削除・伏せ字にしてください。

こんな場面で使う

  • Claude Code 自体の調子が悪い/doctor → /status → /debug → /bug

関連するコマンド · 診断とフィードバック

  • /doctor困ったらまず健康診断
  • /helpヘルプとコマンド一覧を見る
  • /powerup対話型レッスンで機能を学ぶ
  • /debugこのセッションのデバッグログを有効にし、ログを読んで問題を調べます。実行した時点から記録。問題の説明を添えられます。
  • /exitCLI を終了します。接続中のバックグラウンドセッションでは切断だけで、セッションは動き続けます。
  • /feedback製品へのフィードバックを送ります。/bug と同じ画面・同意手順です。
  • /heapdumpJavaScript のヒープスナップショットとメモリー内訳をデスクトップに書き出し、メモリー使用量が多い問題を調べます。報告時は -diagnostics.json だけ添付。.heapsnapshot には会話全体と認証情報が含まれるので共有しないこと。メニューには出ないので全部入力。
  • /release-notesバージョンを選んで更新履歴を表示します。表示はされますが、Claude のコンテキストには入りません。
