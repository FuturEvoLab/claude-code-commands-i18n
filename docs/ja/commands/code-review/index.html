/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

コミット前にバグを確認し、自動修正も可能

英語 code review ＝ コードレビュー

★ 初心者向けスキル¥ 費用が発生する場合あり↗ 外部に送信⇄ ファイルを広く変更

現在の変更（または指定した PR・ブランチ・パス）に正しさのバグがないか調べます。深さを選べ、--fix で修正まで、--comment で GitHub PR／GitLab MR にコメント、ultra でクラウドの詳細レビュー。

おすすめの使い方

コミット前に：/code-review high --fix。他人の PR なら：/code-review high 1234。

別名

/review

安全マーク

¥ 費用が発生する場合あり: 有料の使用量を消費したり、追加料金が発生したりする場合があります。使う前に /usage で確認し、公式の料金説明を確認してください。

↗ 外部に送信: 会話・コード・コメントを他のサービス（Anthropic、GitHub、クラウドセッション、ブラウザー上のサイトなど）に送ったり、リモートに push したりします。内容と送信先を確認してから実行してください。

⇄ ファイルを広く変更: 多くのファイルを一度に変更・復元する場合があります。実行前に Git でコミットかバックアップをし、実行後は /diff で確認してください。

こんな場面で使う

  • コミットや公開の前にチェックしたい/diff → /code-review → /security-review → /verify

関連するコマンド · レビューと検証

  • /runプロジェクトのアプリを起動・操作して、変更の実際の動きを見ます。
  • /run-skill-generatorこのプロジェクト専用のスキルを書き、/run と /verify にクリーンな環境からのビルド・起動・操作方法を教えます。
  • /security-review現在のブランチとリモートの既定ブランチの差分から、インジェクション・認証の問題・データ漏えいなどの危険を探します。origin リモートが必要です。
  • /simplify4 つのレビューエージェントが並行して、変更したコードを再利用・簡素化・効率・抽象度の観点で確認し、修正まで行います。正しさのバグは対象外（それは /code-review）。
  • /ultrareviewクラウドのサンドボックスで複数エージェントによる詳細レビューを行います。推奨は /code-review ultra（/ultrareview は別名）。Pro・Max・Ultra は 3 回無料、その後は使用量クレジットが必要です。
  • /verifyアプリを実際にビルド・起動して結果を観察し、変更が意図どおりか確認します（テストや型チェックだけに頼らない）。手動で呼んだときだけ動きます。
