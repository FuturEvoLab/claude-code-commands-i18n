/Claude Code コマンド一覧

Claude Code の / で始まるコマンドすべてを、やさしい日本語で説明します。英語の意味、できること、いちばん役立つ使い方がわかります。

claude
❯

    やりたいことから探す

    状況を選んでください。コマンドは試す順に並んでいます。

    • Claude が壊したので元に戻したい: /rewind /diff
    • 関係のない別の作業を最初から始めたい: /clear /resume
    • 会話が長くなり、遅い・忘れっぽい: /context /compact /autocompact
    • 昨日の続きをやりたい: /resume /rename /recap
    • 大きな変更の前に、まず計画を見たい: /plan /effort /model
    • Claude にいつも日本語で答えてほしい: /init /memory
    • 料金や使用量を節約したい: /usage /model /effort /context
    • コミットや公開の前にチェックしたい: /diff /code-review /security-review /verify
    • 複数の作業を同時に / 裏で動かしたい: /fork /subtask /background /tasks /batch
    • 繰り返し・決まった時刻に実行したい: /loop /schedule /goal
    • 許可の確認ダイアログが多すぎる: /permissions /fewer-permission-prompts
    • 外部ツールの接続や機能の追加をしたい: /mcp /plugin /skills
    • スライド・デザイン・グラフを作りたい: /slides /design /dataviz /artifacts
    • パソコンを離れてスマホで続けたい: /remote-control /mobile /desktop
    • Claude Code 自体の調子が悪い: /doctor /status /debug /bug
    • 使い方を体系的に学びたい: /powerup /help /insights

    安全マーク

    次のマークが付いたコマンドは慎重に使ってください。

      会話とコンテキスト

      会話の新規作成・圧縮・巻き戻し・再開、Claude の「記憶の容量」の管理

      /clear [name]

      コンテキストが空の新しい会話を始めます。プロジェクトの記憶（CLAUDE.md）は残ります。前の会話は削除されず /resume で戻れます。名前を付けると前の会話にラベルが付きます。

      おすすめの使い方: ある機能が終わり、関係のない次の作業に移るとき：/clear ログイン機能。前の内容に引きずられず、使用量も節約できます。

      /compact [instructions]

      これまでの会話を要約してコンテキストの空きを作り、同じ会話を続けます。「要約で何を残すか」を指示できます。

      おすすめの使い方: 長い会話のあとで：/compact データベース構造と未修正のバグ一覧を残して。

      /context [all]

      コンテキストの使用量と内訳を色付きのマス目で表示し、節約のヒントや容量の警告を出します。all で詳細をすべて表示します。

      おすすめの使い方: Claude が「忘れっぽく」なった、使用量の増えが速いと感じたら、まず /context で大きなファイルやツール出力が原因か確認します。

      /plan [description]

      プランモードに入ります。Claude はまず調査して計画を示し、承認されてからファイルを変更します。作業内容を添えるとすぐ開始。

      おすすめの使い方: 大きな変更の前に：/plan ログインのエラーを直して。計画を確認してから任せます。

      /resume [session]

      ID か名前で以前の会話を再開します。引数なしなら一覧が開きます。バックグラウンドの会話には bg と表示されます。

      おすすめの使い方: 昨日途中でパソコンを閉じたら：今日 /resume で昨日の会話を選んで続きから。

      /rewind

      会話とコード（片方だけも可）を以前のチェックポイントに戻します。選んだメッセージ以降を要約することもできます。ゲームの「セーブデータを読み込む」に近い機能です。

      おすすめの使い方: Claude がファイルを壊してしまったら：/rewind で変更前のメッセージを選ぶと、コードと会話がまとめて元に戻ります。

      /autocompact [auto|<tokens>]

      コンテキストがどれだけ埋まったら自動圧縮するかを設定します（例：500k）。auto でモデルの既定値に戻ります。ユーザー設定に保存され、すぐ反映されます。

      おすすめの使い方: 長い作業で圧縮が頻繁に入るのを避けたいとき：/autocompact 500k。

      /branch [name]

      今の時点で会話の分岐を作って切り替え、別の方向を試せます。元の会話は残り /resume で戻れます。（Git のブランチではなく会話の分岐です。）

      おすすめの使い方: 案 A と案 B で迷ったら：/branch 案Bを試す。だめなら元の会話で A を続けます。

      /btw [question]

      今の会話について、履歴に残さない「ついでの質問」をします。質問なしで実行すると直近の質問と回答を表示します。

      おすすめの使い方: 作業中にエラーの意味だけ知りたいとき：/btw この 404 は何の意味？。本題の流れを乱しません。

      /copy [N]

      直前の回答をクリップボードにコピーします。/copy 2 で 2 つ前の回答。コードブロックがあれば選択画面が出て、一部だけコピーできます。w でファイルに書き出し（SSH 接続時に便利）。

      おすすめの使い方: Claude が書いた文章やコマンドを /copy でそのまま貼り付け。

      /export [filename]

      今の会話をプレーンテキストで書き出します。ファイル名を指定すると直接保存、なしならコピーか保存かを選べます。

      おすすめの使い方: 役に立ったトラブル対応の記録を /export 対応記録.txt で保存して共有。

      /goal [condition|clear]

      完了条件を設定すると、条件を満たすか解除されるまで Claude が複数ターンにわたり作業を続けます。引数なしで現在の目標を表示、clear・stop・off などで途中解除。

      おすすめの使い方: /goal すべてのテストが通る と設定し、全部通るまで任せます。

      /memory

      記憶ファイル CLAUDE.md の編集、「自動メモリー」のオン・オフ、自動で記憶した内容の確認ができます。

      おすすめの使い方: いつも日本語で答えてほしいなら：/memory で CLAUDE.md を開き「常に日本語で回答して」と書きます。

      /recap

      今のセッションの内容を一文で要約します。

      おすすめの使い方: 会議から戻ってどこまで進んだか忘れたら：/recap。

      /rename [name]

      今のセッションの名前を変え、入力欄の上に表示します。名前なしなら会話内容から自動で付けます。

      おすすめの使い方: 複数のセッションを開いているとき：/rename 株価バックテスト にしておくと /resume で見つけやすい。

      モデルと推論

      モデルの切り替え、考える深さや速度の調整

      /model [model]

      AI モデルを切り替え、新しいセッションの既定にも保存します。引数なしで選択画面。対応モデルでは左右キーで推論の深さを調整、行で s を押すとこのセッションだけ切り替えます。

      おすすめの使い方: 簡単な修正は速くて安いモデル、難しいバグは /model opus で強いモデルに。

      /advisor [model|off]

      「アドバイザー」を切り替えます。作業の重要な場面で別のモデルに助言を求めます。fable・opus・sonnet または完全なモデル ID を指定（fable は利用権限が必要）。引数なしで選択画面。

      おすすめの使い方: 普段は速いモデルで作業し、重要な判断だけ強いモデルに見てもらう：/advisor opus。

      /effort [level|auto|status|ultracode [on|off]]

      推論の深さを low〜xhigh、max、auto から設定します。status で現在値を表示。max はこのセッションのみ。ultracode on|off で ultracode を切り替えます。

      おすすめの使い方: 再現しにくいバグの調査：/effort high、誤字の修正だけ：/effort low。

      /fast [on|off]

      高速モード（同じモデルで出力が速くなる）を切り替えます。応答中でも切り替えられますが、進行中のターンは元の速度のまま終わります。料金は公式の fast mode の説明を確認してください。

      おすすめの使い方: 急ぎで大量に生成したいとき /fast on、急がないときは /fast off。

      /output-style [style]

      出力スタイル（回答の書き方）を一覧表示・切り替えします。例：/output-style concise。

      おすすめの使い方: まず引数なしの /output-style で一覧を見て、自分に合うもの（例：簡潔なもの）を選びます。

      プロジェクトとファイル

      プロジェクトを Claude に理解させる、フォルダーを追加する、変更を確認する

      /init

      プロジェクトを読み込んで CLAUDE.md（プロジェクトの説明書）を作ります。以降の新しい会話は毎回これを読みます。Codex や Gemini CLI の設定があれば /import での移行を提案します。

      おすすめの使い方: 新しいプロジェクトでまず /init。そのあと /memory で「日本語で答えて」などの希望を追記します。

      /add-dir <path>

      このセッションで別のフォルダーへのアクセスを追加します（作業場所はそのまま）。パスの途中まで入力すると候補が出て Tab で確定。追加したフォルダーの .claude/ 設定はほとんど読み込まれず、ネットワークパスの多くは追加できません。

      おすすめの使い方: フロントとバックエンドが別フォルダーなら：/add-dir ../backend で両方を見せます。

      /cd <path>

      会話を残したまま、セッションを別のフォルダーに移します。/add-dir との違い：/cd は引っ越し、/add-dir は入り口を一つ増やすイメージです。

      おすすめの使い方: 違うフォルダーで始めてしまったら：/cd ~/projects/website でやり直し不要。

      /diff

      作業ツリーの変更（Claude がこれまでに行った編集を含む）を確認します。

      おすすめの使い方: 「できました」と言われたら、コミット前に /diff で中身を自分の目で確認。

      /import [codex|gemini|cursor] [--dry-run] [--yes]

      OpenAI Codex・Google Gemini CLI・Cursor の設定（指示ファイル、MCP サーバー、コマンド、サブエージェント、スキル）を取り込みます。--dry-run はプレビューのみ。一部のクラウド環境では使えません。Cursor からの取り込みには v2.1.265 以降が必要です。

      おすすめの使い方: Cursor から移るとき：まず /import cursor --dry-run で内容を確認してから本番の取り込み。

      /insights

      このマシンでの最近の使い方（よく使うプロジェクト、使い方、つまずきやすい点、試すとよい機能）を分析した HTML レポートを作ります。クラウドセッションでは使えません。

      おすすめの使い方: しばらく使ったら /insights で、まだ使っていない便利な機能を見つけます。

      /team-onboarding

      過去 30 日のセッション・コマンド・MCP の使い方を分析し、新しいメンバーが最初のメッセージとして貼り付けられる Markdown のガイドを作ります。

      おすすめの使い方: 新メンバーが来たら：/team-onboarding でガイドを作って渡します。

      レビューと検証

      バグ・脆弱性の検出、コード整理、実際に動かして確認

      /code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

      現在の変更（または指定した PR・ブランチ・パス）に正しさのバグがないか調べます。深さを選べ、--fix で修正まで、--comment で GitHub PR／GitLab MR にコメント、ultra でクラウドの詳細レビュー。

      おすすめの使い方: コミット前に：/code-review high --fix。他人の PR なら：/code-review high 1234。

      /run

      プロジェクトのアプリを起動・操作して、変更の実際の動きを見ます。

      おすすめの使い方: /run でサイトを起動し、新しいトップページのスクリーンショットを見せてもらう。

      /run-skill-generator

      このプロジェクト専用のスキルを書き、/run と /verify にクリーンな環境からのビルド・起動・操作方法を教えます。

      おすすめの使い方: 起動手順が複雑（先に DB を起動など）なら一度実行。以後は /run だけで済みます。

      /security-review

      現在のブランチとリモートの既定ブランチの差分から、インジェクション・認証の問題・データ漏えいなどの危険を探します。origin リモートが必要です。

      おすすめの使い方: ログイン・決済・個人情報に関わる変更を公開する前に一度実行。

      /simplify [target]

      4 つのレビューエージェントが並行して、変更したコードを再利用・簡素化・効率・抽象度の観点で確認し、修正まで行います。正しさのバグは対象外（それは /code-review）。

      おすすめの使い方: 動くようになったあと、保守しやすくしたいとき：/simplify。

      /ultrareview [PR or branch]

      クラウドのサンドボックスで複数エージェントによる詳細レビューを行います。推奨は /code-review ultra（/ultrareview は別名）。Pro・Max・Ultra は 3 回無料、その後は使用量クレジットが必要です。

      おすすめの使い方: 重要なリリースの前に：/code-review ultra。

      /verify

      アプリを実際にビルド・起動して結果を観察し、変更が意図どおりか確認します（テストや型チェックだけに頼らない）。手動で呼んだときだけ動きます。

      おすすめの使い方: ボタンの動作を変えたら：/verify で実際に開いて押して確認。

      並列・バックグラウンド

      複数の Claude を同時に動かす、バックグラウンドで実行する

      /agents

      新しいバージョンでは案内が表示されるだけです：Claude にサブエージェントの作成・管理を頼むか、.claude/agents/ を直接編集します。v2.1.197 以前は管理画面が開きます。

      おすすめの使い方: 「テスト専門のサブエージェントを作って」と頼むだけで OK。

      /background [prompt]

      今のセッションをバックグラウンドのエージェントとして動かし続け、ターミナルを空けます。最後の指示を添えることもできます。確認は claude agents。

      おすすめの使い方: 30 分かかる作業なら：/bg 終わったら結果を report.md に書いて。

      /batch <instruction>

      大規模な変更を並列で行います。コードを調べて 5〜30 の独立した単位に分けて計画を示し、承認後は単位ごとにバックグラウンドのサブエージェントが独立した worktree で実装・テスト・反映します。Git リポジトリ（または対応する hook）が必要です。

      おすすめの使い方: /batch src/ を JavaScript から TypeScript に移行。

      /fork [prompt]

      今の会話を新しいバックグラウンドセッションに複製し、こちらは作業を続けます。指示を付けると複製がすぐ作業開始。複製は通常、自分用の worktree を作ってから編集します。

      おすすめの使い方: 機能 A の作業中に小さな不具合も直したいとき：/fork フッターのずれを直して。

      /list-agents

      Claude がメッセージを送れるサブエージェント・チームメイト・他のセッションと、その名前を一覧表示します。セッション間メッセージが有効な場合のみ。

      おすすめの使い方: 複数のセッションで連携するとき、お互いの名前を確認。

      /stop

      接続中のバックグラウンドセッションを停止します（記録と worktree は残ります）。止めずに離れたいだけなら /exit か ←。

      おすすめの使い方: バックグラウンドの作業が方向違いになったら：/stop。

      /subtask <task>

      会話全体を引き継いだバックグラウンドのサブエージェントに作業を任せ、終わると結果がこの会話に戻ります。/fork との違い：/subtask は結果が戻り、/fork は独立したセッションです。

      おすすめの使い方: /subtask これらの API のドキュメントを書いて、自分はコードを書き続けます。

      /tasks

      このセッションのバックグラウンド作業（完了したサブエージェントを含む）を確認・管理します。

      おすすめの使い方: テストやサブエージェントを裏で動かしている間に /tasks で進み具合を確認。

      /workflow-authoring

      動的ワークフローのスクリプトを書くための資料を読み込みます。通常は Claude が自動で読み込みます。保存済みスクリプトを手で直す前に実行するとよいでしょう。動的ワークフローが有効な場合のみ。

      おすすめの使い方: 保存したワークフローを手で調整する前に。

      /workflows

      ワークフローの進行画面を開き、実行中・完了済みのワークフローの確認・一時停止・再開・保存ができます。

      おすすめの使い方: 大きな調査や改修のワークフローを動かしているとき、進み具合を見るのに使います。

      自動化とスケジュール

      一定間隔で繰り返す、決まった時刻に実行する、PR を自動修正する

      /loop [interval] [prompt]

      セッションが開いている間、指示を繰り返し実行します。間隔を省略すると Claude がペースを決め、指示を省略すると組み込みの保守用プロンプトか loop.md を実行します。セッションを閉じると止まります。

      おすすめの使い方: /loop 5m デプロイが終わったか確認。パソコンを閉じても動かしたいなら /schedule。

      /autofix-pr [prompt]

      現在のブランチの PR をクラウドセッションが見張り、CI の失敗やレビューコメントがあれば修正を push します。gh CLI とクラウドセッションの利用権が必要です。

      おすすめの使い方: lint だけ任せたいなら：/autofix-pr lint と型エラーだけ直して。

      /deep-research <question>

      マルチエージェントのワークフローです。Web を広く検索し、情報源を取得・照合して、出典付きのレポートにまとめます。バックグラウンドで動きます。

      おすすめの使い方: /deep-research 主要な AI 動画生成ツールの料金と画質の比較。

      /schedule [description]

      クラウドの定期実行タスク（旧 routines）を作成・変更・一覧・実行します。会話形式で設定でき、最近の実行結果も聞けます。Console の API キーでは使えません。

      おすすめの使い方: /schedule 平日の毎朝 9 時に新しい issue をまとめて。

      ページ・スライド・デザイン

      共有できるページ、スライド、デザイン、グラフを作る

      /artifact-capabilities

      アーティファクトで使える実行時機能（コネクターの呼び出し、ファイルのダウンロード提供など）と、自分のアカウントで使えるものの資料を読み込みます。通常は Claude が自動で読み込みます。

      おすすめの使い方: 複数人が入力できる申込ページを作る前に。

      /artifact-diagramming

      アーティファクトで図を描くためのガイドを読み込みます。図が必要な場面、何を描くか、明暗どちらのテーマでも見やすい SVG の書き方。

      おすすめの使い方: わかりやすいシステム構成図がほしいとき。

      /artifacts

      自分が持っている、または共有されたアーティファクト（Web ページ）を一覧表示し、セッションへの追加・ブラウザーで開く・リンクのコピーができます。対応環境のみ。

      おすすめの使い方: 先週作ったダッシュボードを探して続きを編集。

      /dataviz [request]

      グラフ作成のガイドです。データに合う形を選び、役割ごとに色を割り当て、付属スクリプトで色覚多様性への配慮とコントラストを確認します。

      おすすめの使い方: /dataviz この月次売上表を推移グラフにして。

      /design [brief]

      UI のラフ、画面遷移、LP、ポスターを 1 枚のキャンバスに描きます（Claude Design のアーティファクト）。デスクトップのブラウザーで編集し、PNG・PDF で書き出せます。Bedrock や Vertex などでは使えません。

      おすすめの使い方: /design 家計簿アプリの設定画面。

      /design consent

      Claude Design へのアクセスを許可・取り消します。Claude の返答で /design consent を求められたら、自分で入力してください。

      おすすめの使い方: 許可を求められたら自分で /design consent と入力。

      /design-login

      /design-sync 用に claude.ai アカウントで認可します。/design-sync や /design consent に求められたときに使います。

      おすすめの使い方: /design-sync にログインを求められたら実行。

      /design-sync [hint]

      リポジトリの React デザインシステムを変換して Claude Design にアップロードし、実際のコンポーネントでデザインできるようにします。初回は全コンポーネントを検証するため、大きなリポジトリでは数時間かかることも。アップロード先の claude.ai/design は 2026 年 12 月 14 日までに終了予定です。

      おすすめの使い方: 自社のコンポーネント集があるなら：/design-sync Acme DS。上記の終了日に注意。

      /slides [brief]

      説明をもとに Claude Slides のプレゼン（アーティファクト）を作ります。アーティファクト対応のセッションと Slides テンプレートが必要です。

      おすすめの使い方: /slides 四半期の業績レビュー、8 枚、経営層向け。

      プラグイン・スキル・外部連携

      Claude に新しい機能を追加：プラグイン、スキル、MCP、ブラウザー、エディター

      /mcp [reconnect (<server>|all)|enable|disable [<server>|all]]

      MCP サーバーの接続と OAuth 認証を管理します。引数なしで一覧、reconnect・enable・disable とサーバー名か all で直接操作。

      おすすめの使い方: コネクターのエラーや再ログインが必要なとき：/mcp reconnect all。

      /chrome

      Claude in Chrome の設定を行います。

      おすすめの使い方: Chrome 拡張と初めて接続するとき。

      /claude-api [subcommand]

      プロジェクトの言語に合った Claude API と Managed Agents の資料を読み込みます。コードが anthropic を import していると自動で有効。サブコマンドは migrate・upgrade・api-version・cost-optimize・latency-optimize・build-eval・prompt-audit など。

      おすすめの使い方: 自作 AI アプリの API 費用を下げたい：/claude-api cost-optimize。

      /claude-in-chrome [task]

      Claude in Chrome 拡張を通して、ページのテスト・フォーム入力・コンソールログの確認などをブラウザーで行います。Chrome 連携の有効化（例：claude --chrome）が必要です。

      おすすめの使い方: /claude-in-chrome ローカルのサイトで会員登録の流れを試してエラーを報告して。

      /ide

      VS Code や JetBrains などのエディターとの連携を管理し、状態を表示します。

      おすすめの使い方: エディターに Claude の変更が出ないとき、接続を確認。

      /install-github-app

      リポジトリに Claude GitHub App を入れ、必要なら GitHub Actions のワークフローとシークレットも設定します。github.com のリポジトリのみ。

      おすすめの使い方: GitHub の issue や PR で @claude と呼んで作業させたいとき。

      /install-slack-app

      Claude の Slack アプリを入れます。ブラウザーが開き OAuth 認可を行います。

      おすすめの使い方: チームが Slack から Claude を呼びたいとき。

      /plugin [subcommand]

      プラグイン（コマンド・スキル・エージェント・ツールのセット）を管理します。引数なしでメニュー、list・install・enable・disable で直接操作。案内が出たら /reload-plugins。

      おすすめの使い方: /plugin でマーケットプレイスを見て、仕事に合うものを入れます。

      /plugin-authoring

      「mod」（Claude の画面や動作を変える小さな拡張）を書くための資料を読み込みます。組み込みプラグインのスキルで、/plugin でオフにできます。

      おすすめの使い方: 常に横に表示される小さなパネルを作りたいとき。

      /reload-plugins [--force]

      再起動せずにプラグインの変更を反映し、読み込み数とエラーを報告します。読み込む MCP ツールが変わる（プロンプトキャッシュが無効になる）場合は警告して中止、--force で強制。

      おすすめの使い方: プラグインを入れて再読み込みを促されたとき。

      /reload-skills

      スキルとコマンドのフォルダーを再スキャンし、セッション中に追加・変更したスキルをすぐ使えるようにします。増減の数も表示。

      おすすめの使い方: 自作スキルを書いたばかりで、再起動せずに使いたいとき。

      /skill-doctor

      各スキルのコンテキスト消費量と使用頻度を表示し、オフにしてよいスキルを見つけます。

      おすすめの使い方: 定期的に実行して、使っていないスキルを整理。

      /skills

      使えるスキルを一覧表示し、名前・説明・提供元で絞り込めます。t でトークン数順、Space/Enter で Claude や / メニューへの表示を切り替え、Esc で保存して閉じます。

      おすすめの使い方: スキルが多すぎるとき：/skills で t を押して並べ替え、使わないものを非表示に。

      権限とセキュリティ

      Claude にできること・事前確認が必要なことを決める

      /permissions

      ツール権限の「許可・確認・拒否」ルールを管理します。範囲ごとの確認、ルールの追加・削除、作業ディレクトリの管理、「Recently blocked」タブ（自動モードが止めた操作）と分類ルールの確認ができます。

      おすすめの使い方: 毎回「npm test を実行してよいか」と聞かれるのが面倒なら、ここで許可に。

      /auto-mode-setup

      プロジェクトと最近のセッションから autoMode.environment の項目を下書きし、確認後ユーザー設定に保存します。自動モードの判断精度が上がります。バージョンとプランの条件あり。

      おすすめの使い方: 自動モードがいつもの操作を誤って止めるとき。

      /fewer-permission-prompts

      履歴からよく使う読み取り専用の Bash・MCP 呼び出しを探し、優先度順にプロジェクトの .claude/settings.json の許可リストへ追加します。

      おすすめの使い方: 確認ダイアログで何度も止められるときに一度実行。

      /hooks

      フックの設定を確認します。

      おすすめの使い方: フックのせいで編集のたびにエラーが出ていそうなとき、設定内容を確認。

      /privacy-settings

      プライバシー設定を確認・変更します。Pro・Max・Ultra のみ。

      おすすめの使い方: データの扱いに関する設定を確認したいとき。

      /sandbox

      サンドボックスモードを切り替えます。対応プラットフォームのみ。

      おすすめの使い方: よく知らないスクリプトを動かす前にオンに。

      /update-config [request]

      設定の変更（コマンドの許可、環境変数、フックの追加）を言葉で伝えると、Claude が該当の settings.json を編集します。テーマやモデルは /config。

      おすすめの使い方: /update-config ファイル編集のたびに prettier を自動実行。

      設定と表示

      テーマ、色、ステータスライン、ショートカット、音声入力

      /color [color|default]

      このセッションの入力欄の色を設定します：red・blue・green・yellow・purple・orange・pink・cyan。default で戻し、引数なしでランダム。

      おすすめの使い方: 本番環境を扱うセッションは /color red にして注意を促す。

      /config [key=value ...]

      設定画面（テーマ、モデル、出力スタイルなど）を開きます。key=value で直接変更も可能（例：/config theme=dark）。/config --help で使えるキーを表示。

      おすすめの使い方: /config theme=dark で一発でダークテーマに。

      /focus

      フォーカス表示を切り替えます。最後の指示、ツール呼び出しの 1 行要約、最終回答だけを表示。フルスクリーン表示でのみ使えます。

      おすすめの使い方: 途中経過は見ず、結果だけ見たいとき。

      /keybindings

      キーボードショートカットの設定ファイルを開きます。

      おすすめの使い方: よく使う操作を慣れたキーに変更。

      /scroll-speed

      マウスホイールの速度を調整します。フルスクリーン表示のみ、JetBrains のターミナルでは不可。

      おすすめの使い方: 一回で飛びすぎるときに遅く。

      /statusline

      下部のステータスラインを設定します。表示したい内容を言葉で伝えるか、引数なしでシェルのプロンプトから自動設定。

      おすすめの使い方: /statusline 現在のモデルと git ブランチを表示。

      /terminal-setup

      VS Code・Cursor・Devin Desktop・Alacritty・Zed で Shift+Enter の改行を設定します。Apple のターミナルでは Option+Enter の改行とビープ音のオフ、iTerm2 では /copy 用のクリップボード許可を設定。

      おすすめの使い方: Enter で書きかけの指示が送られてしまうなら一度実行。

      /theme

      配色テーマを変えます：auto（ターミナルに合わせる）、ライト／ダーク、色覚多様性に配慮したテーマ、ANSI テーマ、カスタムテーマ。

      おすすめの使い方: 夜に目が疲れたらダークテーマに。

      /tui [default|fullscreen]

      ターミナル UI の描画方式を設定し、会話を保ったまま再起動します。fullscreen はちらつかない全画面表示。引数なしで現在の方式を表示。

      おすすめの使い方: 画面がちらつくなら：/tui fullscreen。

      /voice [hold|tap|off]

      音声入力を切り替えます。hold（押している間）・tap（タップで開始）を指定可能。Claude.ai アカウントが必要。

      おすすめの使い方: 入力が遅いときは日本語で話して指示。

      アカウントと使用量

      ログイン、使用量や料金の確認、プランのアップグレード

      /usage

      このセッションの費用、今日・今週・今月の支出、プランの使用量上限、利用統計を表示します。サブスクリプションでは上限に数えられる内訳も表示。/stats は統計タブで開きます。警告にはそれぞれ原因と一行の対処法が表示され、f で対処をまとめて適用できます。

      おすすめの使い方: 上限が心配なら /usage で確認し、安いモデルに替えるか判断。

      /login

      Anthropic アカウントにログインします。

      おすすめの使い方: パソコンを替えたとき、ログインが切れたとき。

      /logout

      Anthropic アカウントからログアウトします。

      おすすめの使い方: 共用パソコンで使い終わったとき。

      /passes

      Claude Code の 1 週間無料体験を友人に共有します。対象アカウントのみ表示。

      おすすめの使い方: 友人に試してもらう。

      /rate-limit-options

      claude.ai の使用量上限で止まったときの選択肢を表示します：リセット後に自動で続ける、クレジットを追加、プランを上げる。claude.ai のサブスクリプションが必要。

      おすすめの使い方: 夜間の作業が上限で止まったら「リセット後に自動で続ける」を選ぶ。

      /status

      設定の「ステータス」タブを開き、バージョン・モデル・アカウント・接続状況を表示します。応答中でも使えます。

      おすすめの使い方: 人に相談する前に /status の画面を撮っておく。

      /upgrade

      上位プランへのアップグレードページをブラウザーで開きます。

      おすすめの使い方: いつも使用量が足りないとき。

      /usage-credits

      上限に達したときにクレジットを設定・申請します。請求設定ページを開くか、Team／Enterprise で請求権限がない場合は管理者に申請を送ります。旧名 /extra-usage。

      おすすめの使い方: チームの上限に達したら管理者に申請。

      クラウド・リモート・他のデバイス

      デスクトップアプリ、スマホ、Web、クラウドの間で作業を引き継ぐ

      /desktop

      今のセッションを Claude Code のデスクトップアプリで続けます。macOS か x64 Windows と Claude のサブスクリプションが必要。

      おすすめの使い方: ターミナルからグラフィカルなアプリに移りたいとき。

      /mobile

      Claude モバイルアプリのダウンロード用 QR コードを表示します。

      おすすめの使い方: スマホで進み具合を見たり操作したりしたいとき。

      /remote-control

      このセッションを claude.ai（Web やスマホ）から操作できるようにします。claude.ai のサブスクリプションが必要。

      おすすめの使い方: パソコンで作業を動かしたまま外出し、スマホから指示：/rc。

      /remote-env

      CLI からクラウドセッションを始めるときの既定の環境を選びます。

      おすすめの使い方: 複数のクラウド環境があるとき既定を決める。

      /setup-bedrock

      ウィザードで Amazon Bedrock の認証・リージョン・モデルを設定します。CLAUDE_CODE_USE_BEDROCK=1 を設定するまでメニューに出ないので、全部入力します。

      おすすめの使い方: 会社で AWS 経由で Claude を使うとき。

      /setup-vertex

      ウィザードで Google Cloud Agent Platform の認証・プロジェクト・リージョン・モデルを設定します。CLAUDE_CODE_USE_VERTEX=1 を設定するまでメニューに出ないので、全部入力します。

      おすすめの使い方: 会社で Google Cloud 経由で Claude を使うとき。

      /teleport

      クラウドのセッションをこのターミナルに取り込みます（ブランチと会話を取得）。claude.ai のサブスクリプションが必要。

      おすすめの使い方: Web 版で始めた作業をローカルで続ける。

      /web-setup

      ローカルの gh CLI の認証情報を使って、クラウドセッション用に GitHub アカウントを接続します。

      おすすめの使い方: クラウドセッションを初めて使う前に。

      診断とフィードバック

      困ったときはここから

      /doctor [prompt-audit [path]]

      インストール・設定・拡張・CLAUDE.md の問題を診断し、修正案を出します。確認後に Claude が修正。prompt-audit で指示ファイルの監査に切り替え。

      おすすめの使い方: 原因不明の不具合が起きたら、まず /doctor。

      /help

      ヘルプと使えるコマンドを表示します。

      おすすめの使い方: コマンド名を忘れたら /help、または / と数文字で絞り込み。

      /powerup

      アニメーション付きの短い対話型レッスンで Claude Code の機能を学べます。

      おすすめの使い方: 初心者がまとめて学ぶのに最適。

      /bug [report]

      不具合の報告や会話の共有をします。添付する履歴の量を選び、同意画面で確認してから送信されます。

      おすすめの使い方: 明らかに Claude Code 自体の不具合に出会ったとき。

      /debug [description]

      このセッションのデバッグログを有効にし、ログを読んで問題を調べます。実行した時点から記録。問題の説明を添えられます。

      おすすめの使い方: /debug MCP サーバーにつながらない。

      /exit

      CLI を終了します。接続中のバックグラウンドセッションでは切断だけで、セッションは動き続けます。

      おすすめの使い方: 今日の作業を終えるとき。

      /feedback [report]

      製品へのフィードバックを送ります。/bug と同じ画面・同意手順です。

      おすすめの使い方: ほしい機能があれば伝える。

      /heapdump

      JavaScript のヒープスナップショットとメモリー内訳をデスクトップに書き出し、メモリー使用量が多い問題を調べます。報告時は -diagnostics.json だけ添付。.heapsnapshot には会話全体と認証情報が含まれるので共有しないこと。メニューには出ないので全部入力。

      おすすめの使い方: 数 GB のメモリーを使っているとき、報告用に。

      /release-notes

      バージョンを選んで更新履歴を表示します。表示はされますが、Claude のコンテキストには入りません。

      おすすめの使い方: アップデート後に新機能を確認。

      /restart

      Claude Code を再起動してこのセッションを再開し、インストール済みの更新を反映します。Pro・Max・Ultra と、macOS／Linux のネイティブインストールが必要（WSL 不可）。

      おすすめの使い方: 下部に更新の案内が出たら実行。
