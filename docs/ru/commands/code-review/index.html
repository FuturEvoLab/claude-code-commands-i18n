/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

Найти ошибки перед коммитом и при желании исправить

англ. code review ＝ ревью кода

★ С чего начатьНавык¥ Может стоить денег↗ Отправляет данные наружу⇄ Массовые изменения файлов

Проверяет текущий diff, а также PR, ветку или путь на ошибки в логике. --fix применяет найденные исправления, --comment публикует замечания в GitHub PR или GitLab MR, ultra запускает глубокую проверку в облаке.

Лучшее применение

Перед коммитом: /code-review high --fix. Для PR: /code-review high 1234.

Псевдонимы

/review

Метки безопасности

¥ Может стоить денег: Может расходовать платные лимиты или приводить к дополнительной оплате. Сначала проверьте /usage и официальные цены.

↗ Отправляет данные наружу: Отправляет разговор, код или комментарии в другой сервис (Anthropic, GitHub, облачные сессии, сайты в вашем браузере) или отправляет изменения в удалённый репозиторий. Сначала проверьте, что и куда уходит.

⇄ Массовые изменения файлов: Может изменить или откатить сразу много файлов. Сначала сделайте коммит или резервную копию, а после проверьте изменения через /diff.

Когда пригодится

  • Проверить работу перед коммитом или выпуском/diff → /code-review → /security-review → /verify

Похожие команды · Ревью и проверка

  • /runЗапускает приложение проекта и управляет им, чтобы увидеть изменение в работе.
  • /run-skill-generatorПишет навык для проекта, который учит /run и /verify собирать и запускать ваше приложение и управлять им в чистом окружении.
  • /security-reviewАнализирует diff вашей ветки относительно ветки по умолчанию в origin на уязвимости: инъекции, проблемы с авторизацией, утечки данных.
  • /simplifyЧетыре агента параллельно проверяют изменённый код на повторное использование, простоту, эффективность и уровень абстракции, затем применяют исправления.
  • /ultrareviewГлубокая проверка несколькими агентами в облачной песочнице.
  • /verifyСобирает и запускает ваше приложение и наблюдает за ним, чтобы убедиться, что изменение работает, а не полагаться только на тесты или проверку типов.
