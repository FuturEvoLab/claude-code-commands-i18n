/code-review[low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

커밋 전에 버그 검사, 필요하면 수정까지

영어 code review ＝ 코드 리뷰

★ 여기서 시작스킬¥ 비용이 들 수 있음↗ 외부로 데이터 전송⇄ 파일을 대량 변경

현재 diff, 또는 PR·브랜치·경로를 대상으로 정확성 버그를 검토합니다. --fix는 지적 사항을 적용하고, --comment는 GitHub PR이나 GitLab MR에 댓글을 남기며, ultra는 클라우드에서 심층 리뷰를 실행합니다.

추천 사용법

커밋 전에: /code-review high --fix. PR을 검토할 때: /code-review high 1234.

별칭

/review

안전 표시

¥ 비용이 들 수 있음: 유료 사용량을 소비하거나 추가 요금이 발생할 수 있습니다. 먼저 /usage와 공식 요금 안내를 확인하세요.

↗ 외부로 데이터 전송: 대화, 코드, 댓글을 다른 서비스(Anthropic, GitHub, 클라우드 세션, 브라우저 안의 사이트)로 보내거나 원격 저장소에 푸시합니다. 무엇이 어디로 가는지 먼저 확인하세요.

⇄ 파일을 대량 변경: 한 번에 많은 파일을 바꾸거나 되돌릴 수 있습니다. 먼저 커밋하거나 백업하고, 실행 후에는 /diff로 검토하세요.

이런 상황에서 사용

  • 커밋이나 배포 전에 점검하고 싶어요/diff → /code-review → /security-review → /verify

관련 명령어 · 리뷰와 검증

  • /run프로젝트의 앱을 실행하고 조작해서 변경이 동작하는 모습을 확인합니다.
  • /run-skill-generator깨끗한 환경에서 앱을 빌드, 실행, 조작하는 방법을 /run과 /verify에 알려 주는 프로젝트 전용 스킬을 작성합니다.
  • /security-review현재 브랜치와 origin 기본 브랜치의 diff를 분석해 인젝션, 인증 문제, 데이터 노출 같은 취약점을 찾습니다.
  • /simplify에이전트 4개가 병렬로 변경된 코드를 재사용, 단순화, 효율, 추상화 수준 관점에서 검토한 뒤 수정을 적용합니다.
  • /ultrareview클라우드 샌드박스에서 여러 에이전트가 심층 리뷰를 합니다.
  • /verify테스트나 타입 검사에만 의존하지 않고, 앱을 빌드하고 실행해서 직접 보며 변경이 제대로 동작하는지 확인합니다.
