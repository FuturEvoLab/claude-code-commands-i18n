/Claude Code 명령어

Claude Code의 모든 슬래시 명령을 쉬운 말로 설명합니다. 무엇을 하는지, 언제 가장 유용한지 알 수 있습니다.

claude
❯

    하고 싶은 일로 명령 찾기

    상황을 고르세요. 명령은 시도할 순서대로 나열됩니다.

    • Claude가 뭔가를 망가뜨려서 되돌리고 싶어요: /rewind /diff
    • 관계없는 작업을 처음부터 시작하고 싶어요: /clear /resume
    • 대화가 길어져서 Claude가 느리거나 자꾸 잊어버려요: /context /compact /autocompact
    • 어제 끝내지 못한 작업을 이어서 하고 싶어요: /resume /rename /recap
    • 큰 변경 전에 계획부터 보고 싶어요: /plan /effort /model
    • Claude가 항상 한국어로 답하게 하고 싶어요: /init /memory
    • 비용과 사용량을 줄이고 싶어요: /usage /model /effort /context
    • 커밋이나 배포 전에 점검하고 싶어요: /diff /code-review /security-review /verify
    • 여러 작업을 동시에 하거나 백그라운드로 돌리고 싶어요: /fork /subtask /background /tasks /batch
    • 작업을 반복하거나 예약해서 실행하고 싶어요: /loop /schedule /goal
    • 권한 확인 요청이 너무 많아요: /permissions /fewer-permission-prompts
    • 도구를 연결하거나 새 기능을 추가하고 싶어요: /mcp /plugin /skills
    • 슬라이드, 디자인, 차트를 만들고 싶어요: /slides /design /dataviz /artifacts
    • 컴퓨터를 떠나 휴대폰으로 이어서 하고 싶어요: /remote-control /mobile /desktop
    • Claude Code 자체가 이상하게 동작해요: /doctor /status /debug /bug
    • Claude Code를 제대로 배우고 싶어요: /powerup /help /insights

    안전 표시

    이런 표시가 붙은 명령은 특히 조심해서 사용하세요.

      대화와 컨텍스트

      대화를 새로 시작, 압축, 되감기, 재개하고 컨텍스트 창을 관리합니다

      /clear [name]

      컨텍스트가 비어 있는 새 대화를 시작합니다. 프로젝트 메모리는 그대로 남습니다. 이전 대화는 삭제되지 않고 /resume으로 다시 열 수 있습니다. 이름을 붙이면 선택 화면에서 이전 대화에 라벨이 붙습니다.

      추천 사용법: 한 기능을 끝내고 관계없는 다음 작업으로 넘어갈 때: /clear 로그인-기능. 이전 내용에 방해받지 않고 사용량도 줄어듭니다.

      /compact [instructions]

      지금까지의 대화를 요약해서 컨텍스트 공간을 확보하고, 같은 대화를 이어갑니다. 지시를 덧붙이면 요약에 무엇을 남길지 정할 수 있습니다.

      추천 사용법: 긴 작업을 한 뒤: /compact 데이터베이스 구조와 미해결 버그 목록은 남겨 줘.

      /context [all]

      컨텍스트 사용량을 색깔 격자로 보여 주고, 최적화 제안과 용량 경고도 표시합니다. all을 붙이면 항목별 내역을 펼쳐 보여 줍니다.

      추천 사용법: Claude가 자꾸 잊어버리거나 사용량이 빠르게 늘 때, /context로 큰 파일이나 도구 출력이 공간을 채우고 있는지 확인합니다.

      /plan [description]

      계획 모드로 들어갑니다. Claude가 수정하기 전에 조사하고 계획을 제안합니다. 설명을 붙이면 그 작업을 바로 시작합니다.

      추천 사용법: 큰 변경 전에: /plan 인증 버그 수정. 계획을 검토한 뒤 승인합니다.

      /resume [session]

      ID나 이름으로 대화를 다시 열거나, 세션 선택 화면을 엽니다. 백그라운드 세션에는 bg 표시가 붙습니다.

      추천 사용법: 어제 작업 도중 노트북을 닫았다면: /resume으로 어제 대화를 골라 이어서 합니다.

      /rewind

      대화나 코드(또는 둘 다)를 이전 체크포인트로 되돌리거나, 선택한 메시지부터 요약합니다.

      추천 사용법: Claude가 여러 파일을 망가뜨렸다면: /rewind를 실행하고 수정 전 메시지를 골라 코드와 대화를 함께 되돌립니다.

      /autocompact [auto|<tokens>]

      컨텍스트 창이 얼마나 찼을 때 자동 압축할지 정합니다. 예: 500k. auto는 모델에 맞춘 기본값으로 되돌립니다. 사용자 설정에 저장되고 바로 적용됩니다.

      추천 사용법: 긴 작업이 잦은 압축으로 끊길 때: /autocompact 500k.

      /branch [name]

      이 지점에서 대화를 분기하고 그쪽으로 전환합니다. 원래 대화는 보존되며 /resume으로 돌아갈 수 있습니다. (Git 브랜치가 아니라 대화의 분기입니다.)

      추천 사용법: 두 가지 방법 중 고민될 때: /branch B안-시도. 실패하면 원래 대화로 돌아가 A안을 계속합니다.

      /btw [question]

      현재 세션에 대해 곁가지 질문을 하되, 그 내용을 대화에는 추가하지 않습니다. 질문 없이 실행하면 가장 최근의 곁가지 질문을 보여 줍니다.

      추천 사용법: 작업 중에 오류의 뜻만 알고 싶을 때: /btw 이 404는 무슨 뜻이야. 본 작업의 흐름이 흐트러지지 않습니다.

      /copy [N]

      마지막 응답을 클립보드에 복사합니다. /copy 2는 끝에서 두 번째 응답을 복사합니다. 코드 블록이 있으면 선택 화면에서 블록 하나만 복사할 수 있고, w를 누르면 대신 파일로 저장합니다(SSH 접속 중에 편리).

      추천 사용법: Claude가 써 준 코드 조각이나 명령을 /copy로 복사해 필요한 곳에 붙여 넣습니다.

      /export [filename]

      대화를 일반 텍스트로 내보냅니다. 이름을 주면 바로 파일로 저장하고, 아니면 복사/저장 대화상자를 엽니다.

      추천 사용법: 도움이 된 디버깅 기록을 보관할 때: /export 디버깅-기록.txt.

      /goal [condition|clear]

      목표를 설정합니다. 조건이 충족되거나 목표가 해제될 때까지 Claude가 여러 턴에 걸쳐 계속 작업합니다. 인수 없이 실행하면 현재 목표를 보여 주고, clear(또는 stop, off 등)로 목표를 지웁니다.

      추천 사용법: /goal 모든 테스트 통과로 설정하고, 테스트가 모두 통과할 때까지 반복하게 둡니다.

      /memory

      CLAUDE.md 메모리 파일을 편집하고, 자동 메모리를 켜고 끄며, 자동 메모리 항목을 보여 줍니다.

      추천 사용법: 항상 한국어로 답하게 하고 싶다면: /memory를 열고 "항상 한국어로 답해 줘" 같은 줄을 추가합니다.

      /recap

      현재 세션을 한 줄로 요약해 줍니다. 원할 때 바로 실행할 수 있습니다.

      추천 사용법: 회의에서 돌아와 어디까지 했는지 잊었을 때: /recap.

      /rename [name]

      세션 이름을 바꾸고 프롬프트 바에 표시합니다. 이름 없이 실행하면 대화 내용으로 이름을 만들어 줍니다.

      추천 사용법: 세션을 여러 개 열어 둘 때: /rename 백테스트로 바꿔 두면 /resume에서 찾기 쉽습니다.

      모델과 추론

      모델, 추론 노력 수준, 속도를 바꿉니다

      /model [model]

      모델을 바꾸고 새 세션의 기본값으로 저장합니다. 인수 없이 실행하면 선택 화면이 열립니다. 지원되는 모델에서는 좌우 키로 노력 수준을 조절하고, 행에서 s를 누르면 이 세션에서만 바꿉니다.

      추천 사용법: 작은 수정은 빠른 모델로 하고, 버그가 어려워지면 /model opus로 바꿉니다.

      /advisor [model|off]

      중요한 순간에 두 번째 모델에게 의견을 묻는 advisor 도구를 켜거나 끕니다. fable, opus, sonnet 또는 전체 모델 ID를 받습니다(fable은 접근 권한이 필요). 인수 없이 실행하면 선택 화면이 열립니다.

      추천 사용법: 평소에는 빠른 모델로 작업하고, 중요한 판단에서만 더 강한 모델의 의견을 받을 때: /advisor opus.

      /effort [level|auto|status|ultracode [on|off]]

      노력 수준을 정합니다: low부터 xhigh까지의 단계, max, auto 중 하나. status는 현재 값을 표시합니다. max는 이 세션에서만 유효합니다. ultracode on|off로 ultracode를 켜고 끕니다.

      추천 사용법: 재현이 어려운 버그를 찾을 때: /effort high, 오타만 고칠 때: /effort low.

      /fast [on|off]

      빠른 모드를 켜고 끕니다(같은 모델, 더 빠른 출력). 응답 도중에도 바꿀 수 있으며, 진행 중인 턴은 원래 속도로 끝납니다. 요금은 공식 빠른 모드 문서를 확인하세요.

      추천 사용법: 시간이 촉박할 때: /fast on, 그렇지 않을 때: /fast off.

      /output-style [style]

      출력 스타일 목록을 보여 주거나 하나로 바꿉니다. 예: /output-style concise.

      추천 사용법: 먼저 인수 없이 /output-style을 실행해 무엇이 있는지 보고, 하나를 고릅니다(예: 더 간결한 스타일).

      프로젝트와 파일

      프로젝트 메모리를 설정하고, 폴더를 추가하고, 변경 사항을 검토합니다

      /init

      새 세션마다 읽는 CLAUDE.md 안내 파일로 프로젝트를 초기화합니다. Codex나 Gemini CLI 설정을 찾으면 /import를 제안합니다.

      추천 사용법: 새 저장소에서 가장 먼저: /init. 그다음 /memory로 내용을 다듬습니다.

      /add-dir <path>

      이동하지 않고 이 세션에서 파일에 접근할 작업 폴더를 추가합니다. 경로 일부를 입력하고 Tab을 누르면 자동 완성됩니다. 추가한 폴더의 .claude/ 설정은 대부분 인식되지 않으며, 네트워크 경로는 대부분 추가할 수 없습니다.

      추천 사용법: 프런트엔드와 백엔드가 나란히 있을 때: /add-dir ../backend.

      /cd <path>

      대화를 유지한 채 세션을 새 작업 폴더로 옮깁니다. /add-dir와 달리 /cd는 세션이 있는 위치 자체를 바꿉니다.

      추천 사용법: 엉뚱한 폴더에서 시작했다면 처음부터 다시 하지 말고: /cd ~/projects/website.

      /diff

      작업 트리의 변경 사항을 검토합니다. 지금까지 Claude가 수정한 내용도 포함됩니다.

      추천 사용법: 커밋하기 전에 /diff로 정확히 무엇이 바뀌었는지 확인합니다.

      /import [codex|gemini|cursor] [--dry-run] [--yes]

      OpenAI Codex, Gemini CLI, Cursor에서 지침 파일, MCP 서버, 명령, 서브에이전트, 스킬을 가져옵니다. --dry-run은 미리 보기만 합니다. 일부 클라우드 제공업체에서는 사용할 수 없고, Cursor 가져오기는 v2.1.265 이상이 필요합니다.

      추천 사용법: Cursor에서 옮겨 올 때: 먼저 /import cursor --dry-run으로 확인한 뒤 실제로 가져옵니다.

      /insights

      이 컴퓨터의 최근 세션을 HTML 보고서로 만들어 줍니다: 프로젝트, 사용 습관, 자주 막히는 곳, 써 볼 만한 기능. 클라우드 세션에서는 사용할 수 없습니다.

      추천 사용법: 몇 주 사용한 뒤 /insights로 아직 써 보지 않은 기능을 찾아봅니다.

      /team-onboarding

      최근 30일간의 세션, 명령, MCP 사용 내역을 분석해서, 새 팀원이 첫 메시지로 붙여 넣을 수 있는 Markdown 가이드를 작성합니다.

      추천 사용법: 새 팀원이 합류하면: /team-onboarding을 실행하고 가이드를 보내 줍니다.

      리뷰와 검증

      버그와 취약점을 찾고, 코드를 정리하고, 앱을 실행해 확인합니다

      /code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]

      현재 diff, 또는 PR·브랜치·경로를 대상으로 정확성 버그를 검토합니다. --fix는 지적 사항을 적용하고, --comment는 GitHub PR이나 GitLab MR에 댓글을 남기며, ultra는 클라우드에서 심층 리뷰를 실행합니다.

      추천 사용법: 커밋 전에: /code-review high --fix. PR을 검토할 때: /code-review high 1234.

      /run

      프로젝트의 앱을 실행하고 조작해서 변경이 동작하는 모습을 확인합니다.

      추천 사용법: /run으로 사이트를 띄우고 새 홈페이지의 스크린샷을 찍게 합니다.

      /run-skill-generator

      깨끗한 환경에서 앱을 빌드, 실행, 조작하는 방법을 /run과 /verify에 알려 주는 프로젝트 전용 스킬을 작성합니다.

      추천 사용법: 시작 절차가 여러 단계일 때(먼저 데이터베이스 실행 등): 한 번 실행해 두면 이후 /run만으로 됩니다.

      /security-review

      현재 브랜치와 origin 기본 브랜치의 diff를 분석해 인젝션, 인증 문제, 데이터 노출 같은 취약점을 찾습니다. origin 원격 저장소가 필요합니다.

      추천 사용법: 인증, 결제, 사용자 데이터와 관련된 변경을 배포하기 전에 실행합니다.

      /simplify [target]

      에이전트 4개가 병렬로 변경된 코드를 재사용, 단순화, 효율, 추상화 수준 관점에서 검토한 뒤 수정을 적용합니다. 정확성 버그는 찾지 않으니, 그런 용도에는 /code-review를 사용하세요.

      추천 사용법: 기능은 동작하는데 코드를 더 깔끔하게 하고 싶을 때: /simplify.

      /ultrareview [PR or branch]

      클라우드 샌드박스에서 여러 에이전트가 심층 리뷰를 합니다. 권장 형식은 /code-review ultra이고, /ultrareview는 별칭입니다. Pro, Max, Ultra에서 무료 3회가 포함되며, 그 뒤에는 사용량 크레딧이 필요합니다.

      추천 사용법: 중요한 릴리스 전에: /code-review ultra.

      /verify

      테스트나 타입 검사에만 의존하지 않고, 앱을 빌드하고 실행해서 직접 보며 변경이 제대로 동작하는지 확인합니다. 직접 실행했을 때만 동작합니다.

      추천 사용법: 버튼 동작을 바꿨다면: /verify로 실제로 버튼을 눌러 보게 합니다.

      병렬 작업과 백그라운드

      여러 에이전트를 동시에 실행하거나 작업을 백그라운드로 보냅니다

      /agents

      서브에이전트를 만들거나 관리하려면 Claude에게 부탁하거나 .claude/agents/를 직접 편집하라는 안내를 표시합니다. v2.1.197 이하에서는 대화형 관리 화면을 열었습니다.

      추천 사용법: 그냥 부탁하면 됩니다: "테스트만 작성하는 서브에이전트를 만들어 줘."

      /background [prompt]

      세션을 분리해 백그라운드 에이전트로 실행하고 터미널을 비워 줍니다. 그 전에 지시를 하나 더 보낼 수도 있습니다. claude agents로 상태를 지켜봅니다.

      추천 사용법: 30분 걸리는 작업이라면: /bg 끝나면 결과를 report.md에 써 줘.

      /batch <instruction>

      큰 변경을 병렬로 진행합니다: 먼저 코드베이스를 조사해 작업을 독립된 단위 5~30개로 나누고 계획을 보여 줍니다. 승인하면 단위마다 백그라운드 서브에이전트가 자체 worktree에서 구현하고 테스트합니다. git 저장소 또는 WorktreeCreate 훅이 필요합니다.

      추천 사용법: /batch src/를 JavaScript에서 TypeScript로 이전.

      /fork [prompt]

      대화를 새 백그라운드 세션으로 복사하고, 사용자는 여기서 계속 작업할 수 있습니다. 프롬프트를 주면 복사본이 바로 시작하며, 보통 먼저 자체 worktree를 만들도록 지시받습니다.

      추천 사용법: 기능 A를 작업하면서 작은 수정도 동시에 하고 싶을 때: /fork 푸터 정렬 고쳐 줘.

      /list-agents

      Claude가 메시지를 보낼 수 있는 서브에이전트, 팀원, 다른 세션을 각각 부를 이름과 함께 나열합니다. 세션 간 메시지 기능이 켜진 곳에서만 쓸 수 있습니다.

      추천 사용법: 여러 세션을 함께 운영할 때 각각의 이름을 확인합니다.

      /stop

      연결된 백그라운드 세션을 정지합니다. 대화 기록과 worktree는 남습니다. 정지하지 않고 분리만 하려면 /exit를 쓰거나 ←를 누르세요.

      추천 사용법: 백그라운드 작업이 엉뚱한 방향으로 갈 때: /stop.

      /subtask <task>

      대화를 물려받는 포크된 서브에이전트를 만들고, 결과를 이곳에 보고하게 합니다. /fork와의 차이: /subtask는 결과를 이곳에 보고하고, /fork는 별도의 세션을 만듭니다.

      추천 사용법: 코딩을 계속하면서: /subtask 이 API 엔드포인트들 문서화해 줘.

      /tasks

      이 세션의 백그라운드 작업을 보고 관리합니다. 끝난 서브에이전트도 포함됩니다.

      추천 사용법: 백그라운드에서 돌리는 테스트나 서브에이전트의 진행 상황을 /tasks로 확인합니다.

      /workflow-authoring

      동적 워크플로 스크립트를 작성하기 위한 참고 자료를 불러옵니다. 보통은 Claude가 알아서 불러오며, 저장된 스크립트를 직접 고치기 전에 실행하세요. 동적 워크플로가 켜진 곳에서만 쓸 수 있습니다.

      추천 사용법: 저장된 워크플로 스크립트를 직접 고치기 전에.

      /workflows

      워크플로 진행 화면을 열어, 실행 중이거나 완료된 워크플로를 지켜보고, 일시 정지, 재개, 저장할 수 있습니다.

      추천 사용법: 오래 걸리는 워크플로를 지켜볼 때 사용합니다.

      자동화와 예약

      일정 간격으로 반복하고, 예약 실행하고, Pull Request를 자동 수정합니다

      /loop [interval] [prompt]

      세션이 열려 있는 동안 프롬프트를 반복해서 실행합니다. 간격을 생략하면 Claude가 스스로 속도를 정하고, 프롬프트를 생략하면 기본 제공 유지 관리 프롬프트나 loop.md를 실행합니다.

      추천 사용법: /loop 5m 배포가 끝났는지 확인해 줘. 컴퓨터가 꺼져 있어도 계속 실행하려면 /schedule을 사용하세요.

      /autofix-pr [prompt]

      현재 브랜치의 PR을 지켜보다가 CI 실패나 리뷰 댓글이 생기면 수정을 푸시하는 클라우드 세션을 시작합니다. gh CLI와 클라우드 세션이 필요합니다.

      추천 사용법: /autofix-pr lint와 타입 오류만 고쳐 줘.

      /deep-research <question>

      웹 검색을 여러 갈래로 수행하고, 출처를 가져와 교차 확인한 뒤, 출처가 달린 보고서를 쓰는 기본 제공 워크플로입니다. 백그라운드에서 실행됩니다.

      추천 사용법: /deep-research 주요 AI 영상 도구의 가격과 품질 비교.

      /schedule [description]

      안내형 대화를 통해 클라우드 예약 작업(이전 이름: routines)을 만들고, 수정하고, 나열하고, 실행합니다. Console API 키로는 사용할 수 없습니다.

      추천 사용법: /schedule 평일 매일 오전 9시에 저장소의 새 이슈를 요약해 줘.

      아티팩트, 슬라이드, 디자인

      공유할 수 있는 페이지, 발표 자료, 디자인, 차트를 만듭니다

      /artifact-capabilities

      커넥터 호출이나 다운로드 제공 같은 아티팩트 실행 기능에 대한 참고 자료와, 내 계정에서 쓸 수 있는 기능을 불러옵니다. 보통은 Claude가 알아서 불러옵니다.

      추천 사용법: 여러 사람이 입력하는 페이지를 만들기 전에.

      /artifact-diagramming

      아티팩트용 다이어그램 안내를 불러옵니다: 다이어그램이 도움이 되는 경우, 무엇을 그릴지, 밝은 테마와 어두운 테마 모두에서 잘 보이는 SVG.

      추천 사용법: 알아보기 쉬운 아키텍처 다이어그램이 필요할 때.

      /artifacts

      내가 소유하거나 공유받은 아티팩트를 나열하고, 하나를 연결하거나, 열거나, 링크를 복사합니다. 아티팩트를 쓸 수 있는 곳에서만 동작합니다.

      추천 사용법: 지난주에 만든 대시보드를 찾아 이어서 편집합니다.

      /dataviz [request]

      차트 디자인 안내: 차트 형태를 고르고, 역할에 따라 색을 지정하며, 함께 제공되는 스크립트로 색맹 안전성과 대비를 기준으로 팔레트를 검증합니다.

      추천 사용법: /dataviz 이 월별 매출 표를 추이 차트로 만들어 줘.

      /design [brief]

      UI 목업, 화면 흐름, 랜딩 페이지, 포스터를 하나의 캔버스 위 아트보드로 초안 작성합니다(Claude Design 아티팩트). 데스크톱 브라우저에서 편집하고 PNG나 PDF로 내보냅니다. Bedrock, Vertex 등 서드파티 플랫폼에서는 사용할 수 없습니다.

      Claude의 Claude Design 접근을 허용하거나 철회합니다. Claude가 /design consent를 실행하라고 하면 직접 입력하세요.

      추천 사용법: 요청을 받으면 /design consent를 직접 입력합니다.

      /design-login

      /design-sync나 /design consent가 요청할 때, claude.ai 계정으로 /design-sync의 디자인 시스템 접근을 승인합니다.

      추천 사용법: /design-sync가 로그인을 요청할 때 실행합니다.

      /design-sync [hint]

      저장소의 React 디자인 시스템을 변환해 Claude Design에 업로드하여, 디자인에 실제 컴포넌트가 쓰이게 합니다. 큰 저장소에서는 첫 동기화에 몇 시간이 걸릴 수 있습니다. 대상은 독립된 claude.ai/design 사이트이며, 이 사이트는 2026년 12월 14일까지 종료됩니다.

      추천 사용법: /design-sync Acme DS (위의 종료 날짜에 주의하세요).

      추천 사용법: /slides 경영진용 분기 리뷰, 8장.

      플러그인, 스킬, 연동

      추천 사용법: /claude-in-chrome 로컬 사이트에서 회원가입 흐름을 테스트하고 오류를 알려 줘.

      /plugin [subcommand]

      플러그인을 관리합니다. 인수 없이 실행하면 메뉴가 열리고, list, install, enable, disable은 바로 실행합니다. 설치 요약에 안내가 나오면 /reload-plugins를 실행하세요.

      추천 사용법: /plugin으로 둘러보고 내 작업에 맞는 플러그인을 설치합니다.

      /plugin-authoring

      mod(확장) 작성용 참고 자료를 불러옵니다. 기본 제공 플러그인에 들어 있는 스킬이며, /plugin에서 끌 수 있습니다.

      추천 사용법: 채팅 옆에 항상 떠 있는 작은 패널을 만들고 싶을 때.

      추천 사용법: 플러그인을 설치한 직후, 다시 불러오라는 안내가 나올 때.

      추천 사용법: 직접 만든 스킬을 방금 작성했고 바로 쓰고 싶을 때.

      추천 사용법: 스킬이 너무 많을 때: /skills에서 t를 눌러 정렬하고, 무겁고 안 쓰는 스킬을 숨깁니다.

      /color [color|default]

      이 세션의 프롬프트 바 색을 정합니다: red, blue, green, yellow, purple, orange, pink, cyan 중 하나. default는 초기화하고, 인수 없이 실행하면 무작위 색을 고릅니다.

      추천 사용법: 운영 환경을 다루는 세션은 /color red로 표시해 둡니다.

      /config [key=value ...]

      테마, 모델, 출력 스타일 등을 바꾸는 설정 화면을 열거나, key=value 형식으로 바로 설정합니다. 예: /config theme=dark. /config --help는 키 목록을 보여 줍니다.

      추천 사용법: /config theme=dark.

      /focus

      마지막 프롬프트, 한 줄짜리 도구 요약, 최종 응답만 보여 주는 화면을 켜고 끕니다. 전체 화면 렌더링에서만 쓸 수 있습니다.

      추천 사용법: 중간 과정은 숨기고 결과만 보고 싶을 때.

      /keybindings

      키보드 단축키 파일을 엽니다.

      추천 사용법: 익숙한 키로 동작을 다시 지정합니다.

      /scroll-speed

      마우스 휠 스크롤 속도를 조절합니다. 전체 화면 렌더링에서만 쓸 수 있으며, JetBrains 터미널에서는 안 됩니다.

      추천 사용법: 휠을 한 칸 굴렸는데 너무 많이 넘어갈 때 느리게 합니다.

      /statusline

      상태 표시줄을 설정합니다. 원하는 내용을 설명하거나, 인수 없이 실행하면 셸 프롬프트를 바탕으로 만들어 줍니다.

      추천 사용법: /statusline 모델과 git 브랜치 표시.

      /terminal-setup

      VS Code, Cursor, Devin Desktop, Alacritty, Zed에서 줄바꿈용 Shift+Enter를 설정합니다. Apple Terminal에서는 Option+Enter를 켜고 경고음을 끄며, iTerm2에서는 /copy를 위한 클립보드 접근을 허용합니다.

      추천 사용법: Enter를 누르면 쓰다 만 프롬프트가 자꾸 전송될 때: 한 번 실행합니다.

      /theme

      색 테마를 바꿉니다: auto, 밝은 테마와 어두운 테마, 색맹 친화 테마, ANSI 테마, 사용자 지정 테마.

      추천 사용법: 밤에는 어두운 테마로 바꿉니다.

      /tui [default|fullscreen]

      터미널 렌더러를 정하고, 대화를 유지한 채 다시 실행합니다. fullscreen은 화면 깜박임이 없는 렌더러입니다. 인수 없이 실행하면 현재 렌더러를 보여 줍니다.

      추천 사용법: 화면이 깜박일 때: /tui fullscreen.

      /voice [hold|tap|off]

      음성 받아쓰기를 켜고 끄거나 모드(hold, tap)를 정합니다. Claude.ai 계정이 필요합니다.

      추천 사용법: 타이핑 대신 말로 지시합니다.

      계정과 사용량

      로그인, 한도와 비용 확인, 업그레이드

      /usage

      세션 비용, 오늘·이번 주·이번 달 지출, 플랜 사용 한도, 활동 통계를 보여 줍니다. 구독 플랜에서 무엇이 한도에 포함되는지도 표시합니다. /stats는 Stats 탭을 엽니다. 경고마다 원인과 한 줄 해결책이 표시되며, f를 누르면 해결책이 적용됩니다.

      추천 사용법: 더 저렴한 모델로 바꿀지 정하기 전에 /usage를 확인합니다.

      /login

      Anthropic 계정에 로그인합니다.

      추천 사용법: 새 컴퓨터를 쓸 때나 세션이 만료되었을 때.

      /logout

      Anthropic 계정에서 로그아웃합니다.

      추천 사용법: 공용 컴퓨터를 쓴 뒤에.

      /passes

      친구에게 Claude Code 무료 1주일 이용권을 공유합니다. 자격이 있는 계정에만 표시됩니다.

      추천 사용법: 친구가 써 볼 수 있게 초대합니다.

      /rate-limit-options

      claude.ai 한도에 걸려 작업이 막혔을 때 계속하는 방법을 보여 줍니다: 기다렸다가 자동으로 이어서 하기, 사용량 크레딧 추가, 업그레이드. claude.ai 구독이 필요합니다.

      추천 사용법: 밤새 작업이 막혔다면: 한도가 초기화된 뒤 자동으로 이어서 하기를 선택합니다.

      /status

      설정 화면의 Status 탭을 엽니다: 버전, 모델, 계정, 연결 상태. Claude가 응답하는 중에도 동작합니다.

      추천 사용법: 도움을 요청하기 전에 /status 화면을 캡처해 둡니다.

      /upgrade

      브라우저에서 업그레이드 페이지를 엽니다.

      추천 사용법: 한도에 자주 걸릴 때.

      /usage-credits

      사용량 크레딧을 설정하거나 요청합니다. 결제 권한이 없는 Team 및 Enterprise 구성원은 관리자에게 요청을 보냅니다. 이전 이름은 /extra-usage입니다.

      추천 사용법: 팀의 사용량이 바닥나면 관리자에게 크레딧을 요청합니다.

      클라우드, 원격, 다른 기기

      데스크톱, 모바일, 웹, 클라우드 사이에서 작업을 주고받으며 이어 갑니다

      Claude Code Desktop 앱에서 세션을 이어갑니다. macOS 또는 x64 Windows와 Claude 구독이 필요합니다.

      Claude 모바일 앱을 내려받을 수 있는 QR 코드를 보여 줍니다.

      추천 사용법: 휴대폰으로 진행 상황을 따라가고 싶을 때.

      /remote-control

      이 세션을 claude.ai에서 Remote Control로 조작할 수 있게 합니다. claude.ai 구독이 필요합니다.

      추천 사용법: 작업을 실행해 둔 채 휴대폰으로 지시하고 싶을 때: /rc.

      /remote-env

      CLI에서 시작하는 클라우드 세션의 기본 클라우드 환경을 고릅니다.

      추천 사용법: 환경이 여러 개일 때 기본값을 정합니다.

      /setup-bedrock

      마법사를 통해 Amazon Bedrock 인증, 리전, 모델 고정을 설정합니다. CLAUDE_CODE_USE_BEDROCK=1을 설정하기 전에는 메뉴에 보이지 않으니 전체 이름을 직접 입력하세요.

      추천 사용법: 회사에서 AWS를 통해 Claude를 쓸 때.

      /setup-vertex

      마법사를 통해 Google Cloud의 Agent Platform을 설정합니다. CLAUDE_CODE_USE_VERTEX=1을 설정하기 전에는 보이지 않으니 전체 이름을 직접 입력하세요.

      추천 사용법: 회사에서 Google Cloud를 통해 Claude를 쓸 때.

      /teleport

      클라우드 세션을 이 터미널로 가져오고, 그 브랜치와 대화를 받아옵니다. claude.ai 구독이 필요합니다.

      추천 사용법: 웹에서 시작한 작업을 로컬에서 이어서 합니다.

      /web-setup

      로컬 gh 인증 정보를 사용해 클라우드 세션용 GitHub를 연결합니다.

      추천 사용법: 처음 클라우드 세션을 쓰기 전에.

      진단과 피드백

      추천 사용법: 명령 이름이 기억나지 않을 때: /help, 또는 /와 몇 글자를 입력합니다.

      /powerup

      애니메이션 데모로 Claude Code 기능을 가르쳐 주는 대화형 레슨입니다.

      추천 사용법: 처음 시작하는 사람에게 가장 체계적인 출발점입니다.

      /bug [report]

      버그를 신고하거나 대화를 공유합니다. 기록을 얼마나 포함할지 직접 고르고, 전송 전에 확인합니다.

      추천 사용법: Claude Code 자체가 이상하게 동작할 때.

      /debug [description]

      지금부터 디버그 로그를 켜고, 세션 디버그 로그를 읽어 문제를 해결합니다. 문제 내용을 설명할 수도 있습니다.

      추천 사용법: /debug MCP 서버 연결이 계속 실패해.

      /exit

      CLI를 종료합니다. 연결된 백그라운드 세션에서는 분리만 되고 세션은 계속 실행됩니다.

      추천 사용법: 오늘 작업을 마칠 때.

      /feedback [report]

      /bug와 같은 대화상자와 동의 단계를 거쳐 제품 피드백을 보냅니다.

      추천 사용법: 원하는 기능을 요청합니다.

      /heapdump

      메모리 사용량이 높을 때 진단할 수 있도록 힙 스냅샷과 메모리 내역을 바탕 화면(Desktop 폴더)에 저장합니다. -diagnostics.json만 공유하세요. .heapsnapshot에는 대화 내용과 인증 정보가 들어 있습니다. 메뉴에는 보이지 않습니다.

      추천 사용법: 메모리 사용량이 폭증했을 때 신고용으로.

      /release-notes

      버전 선택 화면에서 변경 내역을 봅니다. 내용은 Claude의 컨텍스트에 들어가지 않습니다.

      추천 사용법: 업데이트 후 새로운 점을 확인합니다.

      /restart

      설치된 업데이트를 적용하기 위해 Claude Code를 재시작하고 세션을 이어갑니다. Pro, Max 또는 Ultra와 macOS·Linux 네이티브 설치(WSL 제외)가 필요합니다.

      추천 사용법: 업데이트 후 하단에 안내가 나올 때.
